# TC-302 · Excel 导入向导（表头映射 / 行级校验 / 冲突策略）

状态：**accepted** · 依赖：TC-200（工资条项目）、TC-201（成员名单）、TC-203（公式求值器）、TC-300（月份账套）、TC-301（导出空模板） · 最后更新：2026-11-12

设计依据：设计文档 **ch.8** 的「导入校验规则（S08 第三步）」四组规则
（表头映射 / 行级校验 / 冲突策略 / 结果预览）、
**ch.12 界面原型** 的 S08「Excel 导入向导」三步
（上传 → 表头映射 → 校验与入库）与「导入策略」三选项、
**ch.5** 的防错机制 ①身份一致、
**ch.6** 的「members.employee_no 用于 Excel 精确匹配」与 `audit_log` 记录导入、
**ch.9** 的「导入文件只读打开，不复制；解析完成后内存中数值立即写入加密库」。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：ADR-0021（本卡十条口径：**映射目标域 = 固定列 + 工资字段**、
**匹配算法 = 先精确后模糊、模糊需确认**、**不创建新字段**、
**校验分三档（错误 K / 警告 M / 成功 N）**、**身份一致按邮箱找人、姓名不一致记警告并标记不许进发送范围**、
**邮箱是身份主键、工号是辅助键**、**空金额 = 没有这一项**、
**公式列填占位文字静默忽略、填别的报错**、**冲突三选一 + 覆盖前同事务写审计**、
**K>0 禁止入库、M>0 允许入库**、**原文件只读不复制**）。

## 目标

做完之后使用者能干什么：

- **把财务填好的 Excel 导进来**：上传 → 看表头对不对得上 → 看得懂哪些行有问题 → 导进去。
- **错在哪一行说得清**：每个问题都带行号、列名与「怎么改」的说法。
- **导错了能重来**：同月已有数据时可以选「覆盖 / 仅补空 / 取消」，覆盖前留下审计。
- **原件不留在应用里**：Excel 只被读一遍，解析完就进加密库。

## 范围

**做**：

1. `domain/import.rs`：**表头映射规则**（精确 / 模糊 / 未匹配）与
   **行级校验规则**（必填、邮箱格式、成员存在且启用、同月重复、金额可解析、公式列只读）
   —— 纯逻辑，不碰文件、不碰库。
2. `domain/import.rs`：**冲突策略**（覆盖 / 仅补空 / 取消）与结果统计（成功 N / 警告 M / 错误 K）。
3. `infra/import.rs`：用 `calamine` 读 xlsx/xls（**只读打开**）→ 内存里的行 →
   写进 `salary_records`（新迁移 0007），**一个事务**，失败整批回滚。
4. Command：`preview_import`（解析 + 映射 + 校验，出预览，不写库）、
   `commit_import`（按确认的映射与冲突策略写库）。
5. S08 界面：三步向导 + 表头映射表（每列可改映射）+ 导入策略三选一 + 结果预览 + 错误明细下载。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **导入时「创建为新字段」** → 它要动 `salary_fields`（全局配置），
  且当月快照（ADR-0019）冻结后新字段进不了这个月。归 TC-303 或后续卡片。
  本卡对未匹配列只提供「跳过」，并**在界面上明说**那一列的数据不会进库。
- **「映射存成本单位的模板供下月复用」**（设计文档 S08 交互要点里的一句）→
  要一张新表 + 保存/加载界面。归 TC-303 或后续卡片。
- **逐格编辑、公式列重算、合计行** → TC-303。
- **发送范围的身份核对**（警告行的「身份待核对」标记怎么在发送前被挡住）→ TC-401。
- **把导入失败明细写进 `audit_log`** → 本卡只在**覆盖**时写审计（ADR-0021 决策 8）。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 表头映射分三档：精确 / 模糊 / 未匹配。**
导入自己导出的模板（表头 = 显示名）→ 每一列都**精确**命中，不需要用户确认。
表头写「员工邮箱」而字段叫「邮箱」→ **模糊**命中，界面标「待确认」。
表头写「季度补贴」而系统里没有这一列 → **未匹配**，界面标「未匹配」。
*为什么必须有这条*：设计文档 ch.8 明写「优先按字段 key 精确匹配，其次按显示名模糊匹配并让用户确认」。
「自己导出的文件必须无摩擦地导回去」是每月例行流程的底线（ch.5 核心流程 B）。

**2. 映射结果用 key 表示，不用显示名。**
映射预览里每一列都给出**稳定键**（`base_salary` / `name`），改显示名不影响它。
*为什么必须有这条*：ADR-0021 洞一 —— 显示名是用户可改的（TC-200），key 不可改。

**3. 姓名 / 邮箱 / 工号三列固定列必须能对上，对不上则整批不能导。**
三个固定列各自要映射到 Excel 的一列；缺任何一个 → 导入被拒，并说清缺哪个。
*为什么必须有这条*：没有邮箱找不到人（ADR-0016：邮箱全局唯一），没有姓名看不出是谁。

**4. 校验分三档，错误阻断入库、警告不阻断。**
结果预览显示「成功 N 行 / 警告 M 行 / 错误 K 行」；
K>0 时「入库」按钮禁用；M>0 时可以入库。
*为什么必须有这条*：设计文档 ch.8「结果预览」与 S08 交互要点「K>0 时禁止入库」。

**5. 邮箱找不到对应成员 / 成员已停用 → 错误。**
导入的邮箱在成员表里查无此人 → 该行是错误行；查到但已停用 → 也是错误行。
*为什么必须有这条*：ch.8 行级校验「成员是否存在且启用」；
这两类人没有有效收件地址，导进来必然发不出去或发错。

**6. 姓名与成员表不一致 → 警告，且这一行不得进入发送范围。**
导入「张三 / zhangsan@company.com」而成员表里叫「张三丰」→ 该行是**警告**行，
入库，但带「身份待核对」标记。
*为什么必须有这条*：ch.5 防错机制 ①「不匹配的行标红且不允许进入发送范围」。
注意是**标红并排除出发送范围**，不是「整批拒绝」——
一个错别字不该毁掉整批导入。

**7. 同一成员同月出现两次 → 两次都算错误。**
同一份 Excel 里同一个邮箱出现两行 → 两行都标错误（不猜哪一行是对的）。
*为什么必须有这条*：ch.8「同一成员同月不可重复」。
两行都报错是因为没法判断哪行是对的 —— 猜错就是发错工资。

**8. 金额解析：空 = 没有这一项；带千分位与货币符号能解析；解析不出 = 错误。**
`""`（空）→ 该项不存在（不是 0、不是错误）；
`"18,000.00"`、`"¥18000"`、`"-2100"` → 都能解析；
`"一千八"` → 错误。
*为什么必须有这条*：ch.8「金额可解析」；
而「空 = 没有这一项」是 TC-301 说明 Sheet 里写给财务的那句话（「不要填 0」），
导入必须与导出说同一套话。

**9. 百分比列：`%` 去掉后必须在 0–100。**
`"12.50%"` → 12.5 可以；`"120%"` → 错误。
*为什么必须有这条*：设计文档 ch.8 的字段类型表「percent：0–100」。

**10. 公式列：填「公式自动计算」静默忽略；填别的内容 = 错误。**
导入 TC-301 导出的模板 → 公式列那一格写着「公式自动计算」→ **不报错**；
把那一格改成 999 → 该行报错，提示「这一列由系统计算，请清空」。
*为什么必须有这条*：ch.8「公式列只读并忽略用户填写值」；
而 TC-301 导出的模板里那一格**就是**「公式自动计算」——
不特判的话，自己导出的文件每一行都报错。

**11. 冲突策略三选一，且默认不预选。**
导入一个本月已有数据的月份 → 必须先选「覆盖 / 仅补空 / 取消」才能入库。
*为什么必须有这条*：ch.8「同月已有数据时提供「覆盖 / 仅补空 / 取消」三选一」。

**12. 「仅补空」以字段为粒度。**
已有记录里有的字段**保留旧值**，没有的字段才填新值。
*为什么必须有这条*：这个策略的全部意义就在「不覆盖已有的」。

**13. 「覆盖」在写库前留下审计，且审计里没有工资数值。**
覆盖 12 行 → `audit_log` 里有一条 `action=import` 的记录，
`detail_masked` 里只有行数与动作，**搜不到任何金额数字**。
*为什么必须有这条*：ch.8「覆盖前生成变更审计」+ 红线 2（数值不进日志）。

**14. 入库是一个事务：中途失败整批回滚。**
故意让第 5 行写入失败 → 库里**一行都没有**（不是写了 4 行）。
*为什么必须有这条*：设计文档 S08「入库为事务，失败整批回滚」。

**15. 原文件只读打开，不复制进应用目录。**
导入一个 xlsx → 解析完成后，数据目录的 `exports/` 与任何子目录里**都没有**那个 xlsx 的副本。
*为什么必须有这条*：ch.9「导入文件只读打开，不复制」+ 数据最小化。

**16. 导入后能读回来：记录数与导入行数一致，公式列是系统算出来的值。**
导入 42 行 → 库里 42 条记录；「实发工资」列的值是**系统算的**，不是 Excel 里写的。
*为什么必须有这条*：验证端到端真的通了，且公式列走的是 TC-203 的求值器。

**17. 错误明细可下载，且明细里没有工资数值。**
有错误行时能导出一份 xlsx 明细，里面有行号、列名、问题描述，
**没有**任何金额数字。
*为什么必须有这条*：ch.8「错误行可下载明细 xlsx」+ 红线 2。

**18. 门禁九项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。九项按名字：Rust 格式、
前端类型检查、设计 Token、Token 引用可解析、敏感数据未进 git、
Rust 静态检查（clippy `-D warnings`）、Rust 单测、加密栈链接、前端构建。
*为什么必须有这条*：本卡第一次引入「读用户文件」与「批量写库」，
「敏感数据未进 git」这项第一次被压测（导入的 Excel 不能落在仓库里）。

**验收中发现并当场修的缺陷（两条，都是真问题）**

1. **`evaluate_formula_fields` 把 `text_fields` 丢了**（TC-203 的缺陷，本卡验收撞出）。
   它内部构造 `EvalContext` 时写死 `text_fields: BTreeSet::new()`，
   于是「拿文本字段做算术 → 类型错误」（TC-203 标准 7）**只在单元测试里成立**，
   生产路径报的是「未知」。已修：加参数并透传；
   TC-203 的评审记录补了「TC-302 验收时补记的一处缺陷」一节。
2. **「这一行没填」的字段曾让整批导入失败**（本卡自己的口径缺陷）。
   `net_pay` 的默认公式引用具体字段名；「仅补空」策略下已有记录只有 `base_salary`
   → 公式报「引用了不存在的字段」→ 整批失败。**一个没这项奖金的人反而拿不到工资条**。
   已定语义并实现（ADR-0021 洞六）：**配置里有、这一行没填 → 按 0 算**
   （设计文档 S07 的赵六行「个税 —」照样算出实发 13,100.00 正是这个语义）；
   **配置里根本没有的字段名 → 仍然报错**（TC-203 标准 3 不松）。
   修正落在 `domain/record.rs`（行求值），表达式求值器 `domain/formula.rs` 的沙箱边界未动。

**口径统一的顺手重构**

- **行求值收敛到一份**：`commands::fields::evaluate_row`（TC-203 建的）与
  本卡的导入求值原来是两处相似逻辑。已抽出 `domain/record.rs`（求值 + values_json
  序列化 + 校验和），Command 与导入都走它 —— 「预览看到的」「导进去的」
  「将来 TC-401 发出去的」必然是同一个数（ADR-0018 的同一条道理）。
- 新增 `DbState::write_tx`：事务需要 `&mut Connection` 而 `write` 给 `&Connection`；
  与 `write` 同样的只读拦截，事务不是绕过只读的门。

**要认的账（本卡遗留的边界，不是缺陷）**

- **S08 界面只做了结构走查**（浏览器预览模式下看过三步布局与文案）。
  「选文件 → 映射 → 入库」的完整交互链需要真机（plugin-dialog 与 invoke 在浏览器里不可用），
