# TC-600 · 发布产物与一页安装说明

状态：**in_progress** · 依赖：TC-000（工程骨架与发布脚本链） · 最后更新：2026-11-12

设计依据：设计文档 **ch.10**（「打包 / 签名 / 公证 / 分发」「随包附 SHA-256 校验值与安装说明」
「升级：v1 手动下载新 dmg（覆盖安装保留数据）；v2 再评估 tauri-plugin-updater」）、
**ch.15**（本机「0 valid identities」的实测）、**ADR-0002**（不购买 Apple Developer Program → 未签名内部分发）、
**ADR-0008**（dmg 由 hdiutil 产出，不依赖 Finder）、**ADR-0009**（钥匙串 ACL 认 cdhash → 重编译即重授权）、
**ADR-0013**（多机交接靠「导出加密备份 → 新机恢复」）、**ADR-0012**（数据目录跟 `app_data_dir()` 走）、
`../PREP-CHECKLIST.md` §4 **P6 发布**。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：**ADR-0028**（本卡七条口径：**v1 不签名不公证**、**分发判据是 quarantine 属性而不是介质名称**、
**首选 U 盘与局域网共享**、**手动放行的确切位置写进说明**、**钥匙串弹窗必须点「允许」**、
**`spctl` 预期失败是事实不是缺陷**、**产物不入 git**）。

验收期追加两条（同源于真机验收撞出的缺陷，口径见评审记录）：
**ADR-0029**（重新初始化 = 把读不出来的旧库**改名移走**，不删；错误页三条真能点的路）、
**ADR-0030**（开发构建与发布构建**分数据目录**，根治两边互撞钥匙串密钥）。

## 目标

做完之后：

- **使用者拿到一个 dmg 就能装上并打开**：装之前能校验、装的时候知道为什么要点一次「仍要打开」、
  装完第一次启动不会因为钥匙串弹窗点错而卡死。
- **「升级后钥匙串授权会重置」这件事被写在纸上**：为什么重置、点哪个按钮、点错会怎样。
- **卸载与数据位置一页查清**：卸载 ≠ 删数据，工资记录留在哪、怎么彻底清空。
- **发布是一条可重复执行的命令**：不依赖 GUI 会话，不靠记忆。

## 范围

**做**：

1. 跑通并加固 `scripts/release.sh`（构建 → 制 dmg → 校验和 → Gatekeeper 检查），
   修掉跑通过程中暴露的缺陷。
2. **dmg 里随包附安装说明**：`make-dmg.sh` 把 `docs/安装说明.md` 放进 dmg 根部，
   与 `薪邮.app` 并列 —— 「随包附」是字面意义上的随包，不是「另外发一个文件」。
3. `docs/安装说明.md`：**一页**的安装说明，六节齐全
   （校验 / 放行 / 钥匙串弹窗 / 首启 / 卸载与数据位置 / 出问题怎么办），正文汉字数 ≤ 900 字。
4. **分发判据写进说明**：能不能免手动放行，由「文件带不带 `com.apple.quarantine`」决定，
   不由介质名称决定；附一条自查命令。
5. **未签名的三条真相写进说明**：每个新版本手动放行一次 / 升级后钥匙串授权重置 /
   `spctl` 预期失败。
6. 一条**发布记录**（版本、体积、SHA-256、构建时间、universal 架构证据），
   让每次分发可追溯。
7. 门禁与发布链的关系：产物**不入 git**，`git status` 保持干净。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **代码签名与 Apple 公证** → 无证书（ADR-0002 / 决策 D8）。`sign.sh` / `notarize.sh` 留在仓库里，
  `release.sh --signed` 才走；将来买了 Developer ID 另开一卡（编号届时再发，不在看板外占号）。
- **自动更新（`tauri-plugin-updater`）** → ch.10 明确 v2 再评估。
- **内网下载页 / MDM 托管 / 灰度分发** → v1 人工分发（ch.10 的分发形态是「企业内部渠道」）。
- **升级流程演练** → **TC-601**（需要「机器上已经装过旧版本」的状态，本卡造不出来）。
- **多机数据同步** → ch.10 明确：交接靠「导出加密备份 → 新机恢复」（TC-104 已结案）。
- **P6 验收里的「试发一封」** → 需要真实 SMTP 凭据，归 **TC-501**（外部输入阻塞）。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 一条命令产出完整发布产物。**
`bash scripts/release.sh` 从干净状态跑完，退出码 0；`artifacts/` 下出现
`薪邮-0.1.0.dmg` 与 `薪邮-0.1.0.dmg.sha256`。
*为什么必须有这条*：发布必须是**一次操作**，不是「我记得先构建再制 dmg 再算校验和」。

**2. universal 二进制证据。**
`lipo -archs` 输出的架构集合恰为 `x86_64 arm64`（两架构都有，且不多不少）。
*为什么必须有这条*：ch.10 第 01 步「arm64+x86_64 通用包」；单架构包在另一半机器上根本起不来。

**3. dmg 可挂载可拷贝，且随包带说明。**
`hdiutil attach` 成功 → 卷内同时有 `薪邮.app`、指向 `/Applications` 的符号链接（拖放引导）、
以及一份 `安装说明.md`；`hdiutil detach` 干净卸载。
*为什么必须有这条*：dmg 坏在「双击打不开」比「装不上」更难排查；
而说明若不随包走，到用户手上就只剩一个 dmg，等于没有说明。

**4. 校验和可自校验，且产物被移动后仍能校验。**
`shasum -a 256 -c` 通过；把 dmg 复制到**另一个目录**再校验，**仍然通过**
（校验文件里只有文件名，不记路径）。
*为什么必须有这条*：校验文件里写死路径的话，下载方一改名/换目录就失败，
而失败原因看着像「内容被改过」—— 会引导使用者做错误的排查。

**5. Gatekeeper 预期失败，且说明与实际输出逐字相符。**
`spctl -a -vv` 对未签名 app 的输出被完整记进评审记录；
`docs/安装说明.md` 里引用那一句与它**逐字一致**。
*为什么必须有这条*：ch.10「macOS 15 起，未签名未公证的应用普通用户几乎打不开」——
使用者遇到的第一件事就是这个报错，说明里必须原样出现它，而不是转述成「可能无法打开」。

**6. quarantine 判据可测。**
同一份 dmg：本地拷贝出的副本 `xattr -l` **无** `com.apple.quarantine`；
给另一份副本写上该属性后 `xattr -l` 能看到。安装说明里的两句话与此一致。
*为什么必须有这条*：「U 盘拷贝不过 Gatekeeper、网盘下载要手动放行」是本卡分发建议的唯一依据，
判据必须是**属性**而不是介质名称（同一个飞书云盘链接，浏览器下载和客户端下载的 quarantine 行为不同）。

**7. 安装说明是一页，六节齐全。**
`docs/安装说明.md` 存在，含「校验 / 放行 / 钥匙串弹窗 / 首启 / 卸载与数据位置 / 排查」六节；
**正文汉字数 ≤ 900 字**（口径：去掉标题行后的全部内容，按 CJK 汉字计数，
代码块与路径不计入；验收时用脚本数并把脚本输出贴进评审记录）。
*为什么必须有这条*：ch.10 要求「随包附安装说明」；**一页是硬指标** ——
两页的说明使用者读不完，读不完就等于没有。

**8. 说明里的路径与钥匙串条目名，与代码里的事实一致。**
说明写的数据目录 = `~/Library/Application Support/cn.payslipmailer.desktop/`
（`app_data_dir()` 推出，ADR-0012 §1）；钥匙串条目名 = `cn.payslipmailer.db-key`
（`infra/keychain.rs` 的 `SecretKind::DbKey`）。与代码常量**逐字核对**。
*为什么必须有这条*：卸载说明写错路径 = 使用者以为删了其实没删；
钥匙串条目名写错 = 使用者照着删错条目，或找不到该点「允许」的弹窗。

**9. 卸载 = 删 app，数据仍在原处。**
把 `薪邮.app` 从 `/Applications` 移走后，数据目录与钥匙串条目**都还在**；
说明里写明「彻底清空要走应用内的『清空数据』（TC-105）」。
*为什么必须有这条*：工资记录是要留存的（红线 2 的合规侧），
「卸载」与「删数据」是两件事，差别必须写出来而不是留给使用者猜。

**10. 首启能走到主界面，且不被 Gatekeeper 拦。**
安装后首次启动不出现「无法验证开发者」拦截；应用能建库并进入首启向导（S01）。
*为什么必须有这条*：这是「装上就能用」的最小证据。
**本条不含「试发一封」** —— 那需要真实 SMTP 凭据，归 TC-501。

**11. 发布链不破坏既有门禁。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」（九项）。
*为什么必须有这条*：发布脚本改的是构建配置与打包参数，最容易把别处弄坏，
而「发布能出包」不代表「代码还健康」。

**12. 产物与工作区不进版本库。**
`git status --porcelain` 除本卡文档改动外为空；`git ls-files | grep artifacts` 为空。
*为什么必须有这条*：dmg 是二进制大文件，且它承载「未签名构建」这一事实；
入库会让仓库变重，也让「产物是哪一版」难以追溯（产物应由发布记录 + 校验和定位）。

**S10 卡在哪、为什么必须本人做**

真机实测（应用已装进 `/Applications`，`open` 后弹出的原文照抄）：

```
"薪邮"想要访问你的钥匙串中的密钥"cn.payslipmailer.db-key"。
若要给予许可，请输入"登录"钥匙串的密码。
密码： [          ]  始终允许 / 拒绝 / 允许
```

这是 **macOS 登录钥匙串**的授权框，要**你 Mac 的登录密码**才能点「允许」。
自动化做不了（机器没有、也不该有你的登录密码）—— 本人在真机上点完，
后面的「进主界面」「移走 app 后数据仍在」两段就都通了。

**真机验收撞出来的三处真缺陷（都在这一轮当场修掉）**

这几处不是「顺手发现的」，是**发布版第一次在真机上被人用**才暴露的：

1. **开发构建与发布构建共用一个数据目录 → 必然撞「密钥与数据不匹配」**
   （根因与口径见 [ADR-0030](adr/0030-开发构建与发布构建分数据目录.md)）。
   症状：发布版一启动就死在「没能读到本机状态」那一屏。
   修法：开发构建改用 `cn.payslipmailer.desktop-dev/`，两边彻底不打架。

2. **错误页是一条死路**：文案写着「请先从备份恢复或重新完成初始化」，
   屏上却只有「重试」—— 而重试永远不会成功。
   修法：新增 `reinitialize_local_state` Command（把读不出来的旧库**改名移走**，
   不删）+ 错误页补上「重试 / 从备份恢复 / 重新初始化」三条真能点的路
   （口径见 [ADR-0029](adr/0029-重新初始化的口径.md)）。
   同一条死路在钥匙串引导页也有（那里的「重新初始化」只是跳回首启向导），
   一并改成同一条路。

3. **侧边栏有三个导航项点进去是占位页**：「导出空模板」「发送队列」「安全与备份」。
   真正的导出面板藏在「月度工资表」里，队列界面压根没写。
   修法：新增 `ExportScreen`（选月份 → 导出，与月度工资表共用同一个 `ExportPanel`）、
   新增 `QueuePanel`（批次列表 + 暂停 / 继续 / 中止 / 仅重试失败项，
   复用已结案的 Rust 命令）、「安全与备份」指向 `SettingsPanel`。
   **侧边栏承诺的每一屏都必须存在** —— 否则就是一条死路。

**验收中发现并当场修的缺陷**

1. **release 构建专属的未使用 import**（门禁看不到的那一类）：
   `src-tauri/src/infra/keychain.rs` 顶部 `use std::path::{Path, PathBuf};` 里的 `PathBuf`
   只被 `#[cfg(debug_assertions)]` 的 `dev_keychain_path()` 用到 ——
   **dev profile 的 clippy 与 cargo test 都过，只有 release 构建报未使用告警**。
   已改成只 import `Path`，那处直接写 `std::path::PathBuf`。
   *为什么门禁漏掉*：门禁跑的是 dev profile（`debug_assertions` 开），release 才关。
2. **bash 的全角括号吞变量名**（老坑复发，且是旧脚本里的潜伏 bug）：
   `$VAR（全角` 会被 bash 解析成变量名 `VAR\xef`，配合 `set -u` 直接报 `unbound variable`。
   本卡在 `release.sh` 的 heredoc 里连踩两次（`$TARGET（`、`$ARCHS）`），
   顺带查出 **TC-000 时代的 `notarize.sh` 里有一处同样的潜伏 bug**（`「$PROFILE」`）。
   三处全部改成 `${VAR}`，并写了一条扫描脚本覆盖 `scripts/*.sh`
   （模式 `\$[A-Za-z_][A-Za-z0-9_]*[^\x00-\x7f]`）。
3. **安装说明漏写钥匙串弹窗要输密码**（真机才暴露的错）：
   初稿只写「点『允许』」。实测发现弹窗还要**输入 Mac 登录密码** ——
   使用者照初稿操作会在这一步卡住。已把**弹窗原文**写进说明。
4. `verify-release.sh` 自身的两处错（写脚本时犯的，一并记）：
   判 quarantine 时忘了先拷贝文件就去写属性；以及 `$sec」` 又踩了上面那个全角括号坑。
5. **JSX 里的 `**` 被当字面量显示**（三处：`ExportPanel` 的表头说明、新增的 `ExportScreen` 与 `QueuePanel`）。
   JSX 不渲染 markdown —— `**只有那个月的列**` 在界面上就是一串星号。改成 `<b>`。
6. **浏览器预览模式缺两块假数据**（`previewTemplateHeader` / `listSendBatches`）→
   `npm run dev` 里这两屏永远显示「0 列 + 操作未完成」，样式根本无从调。
   补上与后端同口径的假表头（3 固定列 + 7 字段 = 10 列）与假批次。

**真机上跑通的一条完整流程（本卡的最终验收）**

发布版重装到 `/Applications` → 钥匙串授权 → 首启建档（`Neo@toc-cloud.com`）→ 解锁 →
建月份账套（2026-12）→ **导出空模板**，落盘：

```
~/Library/Application Support/cn.payslipmailer.desktop/exports/薪资模板_2026-12.xlsx  (7359 字节)
```

解出来的表头（从 xlsx 的 sharedStrings 读）：

```
姓名 * | 邮箱 * | 工号 | 基本工资 * | 绩效奖金 | 餐补 | 社保个人 | 公积金 | 实发工资 * | 备注
```

**3 个固定列 + 7 个启用字段 = 10 列**，与 ADR-0020 的口径一字不差；
两个 Sheet（表格 + 填写说明）✓。工资数值一个都没有出现在文件名里（红线 2 ✓）。

**要认的账（本卡遗留的边界，不是缺陷）**
- **P6 验收原文里的「从安装到试发一封 ≤ 10 分钟」被切成两半**：
  「装上能开、能建库」归本卡（可自动化）；「试发一封」需要真实 SMTP 凭据 → **TC-501**（外部输入阻塞）。
- **升级流程演练不在本卡** → **TC-601**（要在「装过旧版本、库里有数据」的机器上做，本卡造不出那个状态）。
- **签名与公证仍未做** → 无证书（ADR-0002 / D8）。`sign.sh` / `notarize.sh` 留着，
  `release.sh --signed` 才走；将来买了 Developer ID 另开一卡。
- **本卡的产物不自动交付**：dmg 只在本机 `artifacts/`，分发方式（U 盘 / 网盘）由使用者按 ADR-0028 选。
