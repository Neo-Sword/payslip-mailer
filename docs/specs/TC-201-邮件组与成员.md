# TC-201 · 邮件组与成员（批量粘贴 / 停用不删）

状态：accepted · 依赖：TC-100（SQLCipher 库）、TC-200（工资条项目） · 最后更新：2026-11-11

设计依据：设计文档 **ch.6 数据设计与保存方式** 的核心表定义（`mail_groups` / `members` /
`group_members` 三张表，「email 格式校验 / UNIQUE」「employee_no 可选，用于 Excel 精确匹配」
「成员可属多组」）；**ch.12 界面原型** 的 S05「邮件组与成员」（组列表 + 成员表格、
「成员可属于多个组」「组内成员可重复归属；停用成员不进入发送范围」「同组邮箱唯一，
导入时自动去重」「批量粘贴接受 TSV/CSV 两列（姓名 邮箱）并预览去重结果」）与
S06「成员新增 / 编辑」（邮箱格式 + 同组唯一实时校验、错误字段红描边、
「修改邮箱后，历史发送日志仍保留原收件地址，便于追溯」）；
**ch.9** 的错误提示三要素与空状态规则；**ch.4** 红线 2（不把个人数据写进日志/错误）与
红线 3（不提供不经二次确认的一键群发入口）。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：ADR-0016（本卡七条口径：**一个邮箱一个人（全局 UNIQUE）**、
**批量粘贴自动去重而编辑表单报错**、**成员只有停用没有删除而邮件组可以删**、
**「邮箱待确认」第三态归 TC-403**、批量粘贴的格式判断是启发式的且**必须先预览**、
用上 TC-102 早就划给本卡的 `INVALID_EMAIL` 码）；
ADR-0004（错误词表先行）；红线 2 / 红线 3。

## 目标

做完之后使用者能干什么：

- **把名单录进来**：从飞书或 Excel 复制一坨「姓名 邮箱」粘进来，先看预览，
  重复的自动去掉，格式不对的行明确告诉你是第几行。
- **按组管理**：建邮件组（全员 / 研发组 / 市场组…），一个人可以属于多个组。
- **让离职的人不再收到信**：停用他 —— 他不进发送范围，但名单里的记录还在。
- **在列表里看见谁有问题**：格式可疑的邮箱（曾有 550 退信）直接标出来。

## 范围

**做**：

1. 迁移 `0004_members.sql`：`mail_groups` / `members` / `group_members` 三张表
   （设计文档 ch.6 的列）。
2. `domain/member.rs`：成员的纯逻辑 —— 邮箱格式校验、批量粘贴的解析
   （TSV/CSV 判定、表头识别、去重）与**行级报错**。
3. `infra/members.rs`：成员与组的读写 —— 列出 / 新增 / 编辑 / 停用 / 启用 /
   组的增删 / 组成员关系的增删。
4. `commands/members.rs`：`list_members` / `list_groups` / `create_member` /
   `update_member` / `set_member_active` / `create_group` / `delete_group` /
   `set_member_groups` / `preview_member_paste` / `paste_members` / `member_count`。
5. S05 界面：组列表（带人数）+ 成员表格（姓名/邮箱/工号/所属组/状态/操作）
   + 「批量粘贴」+ 「＋ 添加成员」+ 「＋ 新建组」。
6. S06 弹窗：姓名 / 工号 / 邮箱 / 所属组（多选）/ 启用开关 /
   「移出全部组」/ 保存；邮箱撞了别人 → 字段下红描边说明。
7. 用上 `INVALID_EMAIL` 码（TC-102 的文件头早就把它划给本卡的成员批量粘贴）。
8. `error.rs` 加成员相关的错误码（按 ADR-0004 词表先行）。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **删除成员** → 本卡**不给**这个操作（ADR-0016 决策 4）。要让某人不再收到信 = 停用。
- **「邮箱待确认」第三态** → TC-403（它才有 550 退信历史）。本卡的状态列显示启用/停用。
- **「私发选中成员」跳到 S11** → 发送侧是 P4（TC-401/402/403）。本卡只把「选中」做出来，
  跳转目标先占位。
- **导出名单（CSV）** → 属于发送历史的凭证导出那一族（TC-403），本卡只留按钮位置。
- **真实名单的验证** → 要等业务方给（只放本机，绝不进 git）。
  本卡只用**假数据**验证机制，验收记录里写明这一点。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 首启后有三张表，且列与设计文档一致。**
`sqlite_master` 里能看到 `mail_groups` / `members` / `group_members`；
`members` 的列是 id / name / email / employee_no / active / note。
*为什么必须有这条*：表结构是后面所有卡的地基。成员表没对齐，
TC-401 的「身份一致」与 TC-302 的「工号精确匹配」都要重新设计。

**2. 邮箱全局唯一。**
加两个邮箱相同的成员 → 第二个被拒；把成员 A 加进两个组 → 成功（多组归属）。
*为什么必须有这条*：一个邮箱一个人，是 S03「三重核对」里「身份一致」的唯一依据。
若只在组内唯一，同一个人在不同组会是两行，核对就没有唯一键了（ADR-0016 洞一）。

**3. 批量粘贴：TSV 与 CSV 都能解析。**
粘 `姓名\t邮箱` 与 `姓名,邮箱` 两种 → 都能解析出成员。
*为什么必须有这条*：设计文档 S05 明写「接受 TSV/CSV 两列」。HR 从 Excel 复制过来是 TSV，
从别处粘过来可能是 CSV —— 只支持一种就有一半人用不了。

**4. 批量粘贴：同邮箱自动去重，并报告去掉了几个。**
粘三行、其中两行邮箱相同 → 预览里显示「将写入 2 位成员，去重 1 条」；
真正写入后名单里是 2 个人（不是 3 个、也不是报错）。
*为什么必须有这条*：设计文档 S05 的页脚原文「同组邮箱唯一，导入时自动去重」。
整批因为两行重复就进不去，是很糟的体验 —— HR 还得回去找哪两行重了。

**5. 批量粘贴：格式非法的行整行跳过，并明确指出第几行、哪个字段。**
粘三行，其中一行邮箱是 `hr@` → 预览显示「第 3 行：邮箱格式不对」，
这一行**不进**名单，另外两行正常进；错误文案里**不回显整行内容**。
*为什么必须有这条*：红线 2 的同族 —— 报错里回显整行就等于把别人的姓名与邮箱
写进了日志与错误信息。

**6. 第一行是表头时自动跳过。**
粘 `姓名\t邮箱\n张三\tzhangsan@company.com` → 表头被跳过，写进去 1 个人。
*为什么必须有这条*：从 Excel 连表头一起复制是常态。
把表头当数据写进去，名单里会多出一个叫「邮箱」的人。

**7. 编辑表单：邮箱撞了别人 → 报错 + 红描边，不静默。**
把成员 A 的邮箱改成成员 B 的邮箱 → 保存被拒，错误落在邮箱字段下方。
*为什么必须有这条*：与批量粘贴的口径**刻意不同**（ADR-0016 洞二）：
批量粘贴是便利功能（去重），编辑表单是精确操作（撞了就是填错了）。

**8. 成员只有停用没有删除。**
`grep -n 'delete_member\|remove_member' src-tauri/src/` 命中 0 次；
S05 的操作列里没有「删除」。
*为什么必须有这条*：与 TC-200 的字段同一口径（红线 8 的同族）。
设计文档的原型里也只有「编辑」。

**9. 停用的成员不进发送范围。**
停用一个成员 → 他仍在名单里（状态显示「停用」）、
但 `list_sendable_members`（给发送侧用的名单）里没有他。
*为什么必须有这条*：设计文档 S05 原话「停用成员不进入发送范围」。
这一条现在就能验（发送侧还没做，但「可发送名单」这个查询可以先有）。

**10. 邮件组可以删，且只解除归属、不删成员。**
删掉「研发组」→ 组没了，组里的成员**仍在名单里**，只是不在任何组里了。
*为什么必须有这条*：删组是常见的整理动作；它若连带删成员，就是误删。
成员本身归「停用/不删」那条管。

**11. 一个人可以属于多个组，重复加入同一组被拒。**
把成员加进「研发组」两次 → 第二次被拒（复合主键）。
*为什么必须有这条*：`group_members` 的复合主键是这条规则的物理保障。

**12. 批量粘贴的报错与日志都不含工资数值与完整名单。**
一次失败的批量粘贴之后，日志里搜不到成员姓名与邮箱；
错误文案里只有行号与字段名。
*为什么必须有这条*：红线 2。名单是个人数据，日志是会被导出的东西。

**13. 门禁九项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。九项按名字：Rust 格式、
前端类型检查、设计 Token（色值只允许出现在 `tokens.css`）、Token 引用可解析、
敏感数据未进 git、Rust 静态检查（clippy `-D warnings`）、Rust 单测、
加密栈链接（`otool`：链 `Security.framework`、零 `libcrypto`/`libssl`）、前端构建。
*为什么必须有这条*：本卡第一次把**个人数据**写进库（名单），
「敏感数据未进 git」与「加密栈链接」两项第一次真正被压测。

### 二、实现期的两个发现

1. **`INVALID_EMAIL` 码用起来了** —— TC-102 的文件头早就把它划给「TC-201 成员邮箱批量粘贴」，
   本卡是它的正主（`domain::member::check_email`）。
2. **表头识别用「第二列像不像邮箱」而不是「第一行是不是已知表头」**——
   Excel 里表头那一列可能被改成「电子邮箱」「E-mail」「email」，认死板会漏。
   所以判断放宽到「像不像邮箱」，代价是**极像邮箱的表头**（比如叫 `a@b.co`）会被当成数据，
   那种表头极少见到。
