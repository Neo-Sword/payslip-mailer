# TC-301 · 按配置导出空模板（Excel）

状态：**accepted** · 依赖：TC-100（SQLCipher 库）、TC-200（工资条项目）、TC-201（成员名单）、TC-300（月份账套） · 最后更新：2026-11-12

设计依据：设计文档 **ch.12 界面原型** 的 S09「按配置导出空白 Excel 模板」
（「表头随 S04 字段配置动态生成」「3 个固定列 + 7 个启用字段 = 10 列」；
固定列 姓名/邮箱/工号；选项：包含「填写说明」Sheet / 包含 2 行示例数据 / 预填成员名单 /
仅导出空白表头；「首行冻结 · 金额列数值格式 + 数据校验 · 扣款项填负数 ·
『实发工资』为公式列，导入时忽略」；「导出文件名含年月便于归档」）、
**ch.8**（「由 rust_xlsxwriter 按 `salary_fields.sort_order` 生成」）、
**ch.6** 磁盘布局（`exports/` = 用户主动导出的 xlsx）、
**ch.4** 红线 2 与数据最小化。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：ADR-0020（本卡九条口径：**3 个固定列 + 启用字段**、**表头取账套快照**
（复用 TC-300 的 `display_fields`）、**导出到 `exports/` 且文件名含年月**、
**公式列不导出数据、单元格写「公式自动计算」**、**选项默认值**（说明 Sheet 开、
示例数据关、预填名单关）、**扣款项填负数写进说明**、**首行冻结 + 数值格式 + 数据验证**、
**金额列的判定**、**文件里没有附件/日志/名单**）。

## 目标

做完之后使用者能干什么：

- **把工资条模板交给财务**：导出��个 xlsx，表头就是公司自己配的那几列，
  姓名/邮箱/工号在最前面，后面是各个工资项。
- **财务不会填错**：说明 Sheet 里写着「扣款项填负数」「公式列不用填」；
  金额列是数值格式、错了会被 Excel 拦下；首行冻结，滚动时表头一直在。
- **导出的是「那个月的列」**：导出 9 月的模板，导出的就是 9 月当时的列 ——
  后来改了工资项配置也不影响它。

## 范围

**做**：

1. `domain/sheet.rs`：**工资表的结构** —— 固定列 + 启用字段、每一列的
   显示名 / 类型 / 是否必填 / 是不是公式列；以及「填写说明」Sheet 的文案。
2. `infra/export.rs`：**用 `rust_xlsxwriter` 生成 xlsx** —— 表头、格式、
   冻结、说明 Sheet、可选的示例数据与预填名单。
3. Command：`export_template`（导出并返回文件路径与表头预览）、
   `preview_template_header`（只看表头，不落文件）。
4. S09 界面：导出选项（四个开关）+ **表头预览** +「⇩ 导出 .xlsx」。
5. 导出文件落在数据目录的 `exports/` 下，文件名含年月。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **导入**（读回这个 xlsx、表头映射、行级校验）→ TC-302。
- **写回工资数据**（逐格编辑、合计行、公式列重算）→ TC-303。
- **公式列在 Excel 里真的用公式算** → 不做。设计文档明确「公式列只读、导入时忽略」，
  由系统算（TC-203 的求值器）。
- **导出多个账套到一个工作簿** → 不做。
- **把导出文件自动发给财务**（邮件）→ 不做。发信是 P4 的事。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 表头 = 3 个固定列 + 启用字段，顺序与设计文档一致。**
导出的表头前 3 列是「姓名 / 邮箱 / 工号」，后面按 `sort_order` 是各个启用字段；
`preview_template_header` 返回的列与导出文件里的表头**一字不差**。
*为什么必须有这条*：设计文档 S09 的「3 个固定列 + 7 个启用字段 = 10 列」是原文。
固定列在前面，导入映射才有确定的锚点。

**2. 表头取的是**账套快照**，不是当前配置。**
导出一个 ready 状态的账套 → 之后在 S04 加字段、改显示名 → 再导出，
表头**与第一次导出完全一致**。
*为什么必须有这条*：设计文档 ch.6「field_snapshot 冻结当月字段定义，
防止事后改字段导致历史错位」。这是本卡与 TC-300 的衔接点。

**3. 停用的字段不进表头。**
停用一个字段 → 导出文件的表头里没有它；隐藏的（`visible = false`）也不进。
*为什么必须有这条*：设计文档 S09 说「启用字段」——
停用与隐藏的字段都不该出现在给财务的表里。

**4. 公式列不导出数据，单元格写「公式自动计算」。**
导出后打开 xlsx → 公式列的示例行里是「公式自动计算」四个字，**不是数字**。
*为什么必须有这条*：设计文档 S09 的原型就是这么画的，
交互要点写「『实发工资』为公式列，导入时忽略」。
写数字会让人以为那是算出来的 —— 导入后系统会重算。

**5. 说明 Sheet 默认包含，且写清了「扣款项填负数」。**
导出后 xlsx 有两个 Sheet：「工资表」与「填写说明」；说明里有「扣款项填负数」这条。
*为什么必须有这条*：设计文档 S09 的「扣款项填负数」是**最容易错**的一条 ——
填正数的社保会让实发工资整个算错。写进文件里，它跟着文件走。

**6. 首行冻结、金额列是数值格式。**
打开 xlsx：向下滚动时表头仍在（冻结首行）；金额列的单元格格式是数值（`#,##0.00`），
不是文本。
*为什么必须有这条*：设计文档 S09 的交互要点「首行冻结 · 金额列数值格式 + 数据校验」。
金额列要是文本，「-2100」会被当字符串，公式列就没法算。

**7. 数据验证在金额列上。**
金额列的单元格带数据验证（不能填非数字）。
*为什么必须有这条*：设计文档 S09 明写「金额列数值格式 + 数据校验」。
让 Excel 在填表时就拦下错，比导入时再报错友好得多。

**8. 默认导出的是空模板（只有表头）。**
不勾任何选项导出 → 表头下面**没有数据行**。
*为什么必须有这条*：这是「导出**空**模板」这个功能的字面。
（示例数据与预填名单都是**显式勾选**才有。）

**9. 导出落在 `exports/`，文件名含年月。**
导出后数据目录的 `exports/` 下有一个 `薪资模板_2026-10.xlsx`。
*为什么必须有这条*：设计文档 ch.6 的磁盘布局 +「导出文件名含年月便于归档」。

**10. 文件里没有附件、日志与成员名单（除非显式勾选预填）。**
默认导出的 xlsx 里没有成员姓名与邮箱。
*为什么必须有这条*：红线 2 与数据最小化。
一个「空模板」里带着 42 个人的邮箱，那不是空模板。

**11. 表头预览与实际导出一致。**
界面上「表头预览」显示的列，与导出文件里的表头一字不差。
*为什么必须有这条*：设计文档 S09 的「表头预览」是给使用者看的承诺 ——
预览说三列、导出十列，就是骗人。

**12. 门禁九项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。九项按名字：Rust 格式、
前端类型检查、设计 Token（色值只允许出现在 `tokens.css`）、Token 引用可解析、
敏感数据未进 git、Rust 静态检查（clippy `-D warnings`）、Rust 单测、
加密栈链接（`otool`：链 `Security.framework`、零 `libcrypto`/`libssl`）、前端构建。
*为什么必须有这条*：本卡第一次引入**文件导出**（写文件到用户能拿到的位置），
「敏感数据未进 git」这一项第一次真正被压测（导出的文件不能落在仓库里）。

**验收中发现并当场修的缺陷**

1. **Sheet 名是 `Sheet1` / `Sheet2`**（标准 5）。
   `rust_xlsxwriter` 默认用序号命名，而 spec 要求「工资表」与「填写说明」——
   财务在两个 Sheet 之间会认错。已加 `worksheet.set_name(...)`，
   并把两个名字提成 `export::SHEET_SALARY` / `export::SHEET_INSTRUCTIONS` 常量。
   ADR-0020 决策 9 已补记这条。
2. **落盘路径散在 Command 层**（标准 9 的可测性）。
   原先 Command 自己拼 `exports_dir(...).join(file_name(...))`，
   「落在 exports/ 里」这条标准就没法被一条断言守住。已把整条路径收进
   `export::target_path(data_dir, year_month, include_members)`，
   Command 只调它 —— **一处口径**。
3. **clippy 三处告警**（标准 12）：`ExportOptions::defaults` 没人用（改为 Command
   真的用它取默认值，而不是手搓一份）、`Ok(...?)` 多余、指令表里 `push` 紧跟
   `Vec::new()`。另有两处 `--all-targets` 才暴露的测试代码告警，一并清掉。

**spec 缺陷修订**

- 标准 5 的措辞「导出后 xlsx 有两个 Sheet：『工资表』与『填写说明』」原是**描述**，
  读起来像「设计文档这么画」。验收时发现实现默认给的是 `Sheet1`/`Sheet2` ——
  也就是说这条标准如果只是「照抄设计文档」，会被实现悄悄放过。
  已把「两个 Sheet **叫什么名字**」明确写进标准 5 与 ADR-0020 决策 9。

**要认的账（本卡遗留的边界，不是缺陷）**

- 导出的是「那个月的列」。HR 改了工资项配置后想导出**新**的表，
  得用**新的账套**或还在草稿的当月账套 —— 这是「历史不被改动」的代价，
  ADR-0020「要认的账」里已经写明，界面上也在导出面板里写了这句提示。
- 「包含 2 行示例数据」「预填成员名单」两个选项的**数据内容**只做了单测覆盖
  （示例行、成员行），界面上的开关还没做端到端点击验证 —— 它们只影响
  「多写几行」，不改变表结构，留到 TC-302 的导入向导一并做界面验证。
