# TC-603 · 必测边界用例（全角数字 / 5000 行）与性能目标实测

状态：**in_progress** · 依赖：TC-602 · 最后更新：2026-11-12

设计依据：设计文档 **ch.13**（「必测边界用例：… 中文全角数字 / 超大 Excel（5000 行）…」、
「性能目标：冷启动 < 2s；5000 行导入 < 8s；100 封队列（限速下）无内存增长；主界面交互响应 < 100ms」）。

> **引用口径**：本卡引用设计文档一律用**章号**，不写行号。

## 目标

- ch.13 列的两条**从未实现/从未测过**的边界用例真正落地：中文全角数字能解析、5000 行 Excel 导入能过。
- ch.13 的四条性能目标**第一次被实测**：有数字、有对比、不达标当场改，不留「应该没问题」。

## 范围

**做**：

1. **中文全角数字**：新增 `util::normalize_fullwidth`（全角 ASCII 区与半角差 0xFEE0，
   只转金额五类：数字 / 小数点 / 加号 / 减号 / 百分号），接入**四个解析点**：
   `domain::import::parse_amount`（Excel 导入）、`domain::record::evaluate_row`
   （预览/核对/发送共用的行求值 —— 逐格编辑进的是这里）、`infra::records::period_totals`
   （合计行）、`commands::fields::evaluate_formula`（公式试算的样例值）。
   每个接入点都配测试。
2. **超大 Excel 5000 行**：一条验收测试——5000 行（含校验警告、错误行、空值）的导入预览
   在测试里跑通，且时间写入评审记录。
3. **四条性能目标的实测**：冷启动、5000 行导入耗时、100 封队列的内存（前后 RSS 对比）、
   主界面交互响应（解锁→工作台的可观察延迟）。**实测数字写进评审记录**，不达标就当场改。

**不做**：

- 性能**优化**本身：本卡先测。测出来不达标才优化，且优化学单独记（本卡评审记录里列）。
- 每一条边界用例都做 UI 层人工复验 → 自动化测试 + 一次真机导出/导入走查足够。
- 「日志满 2 年归档」→ 它是留存口径（不删即合规），不是可执行的用例，ch.13 列出但它
  没有「要跑什么」的判据，本卡不造一个。

## 验收标准

**1. 全角金额四路通。**
`cargo test fullwidth` 全绿：导入解析、行求值、合计、公式试算四个点，
全角数字「１８５００」与半角「18500」结果一致；不属于金额的全角字符（如括号）依旧报错。
*为什么必须有这条*：ch.13 明列「中文全角数字」。它不只是导入的问题 ——
同一串字符串进库后还要被求值与合计，所以四个点都要接，漏一个就是「导得进、算不对」。

**2. 5000 行导入跑得通。**
测试里构造 5000 行的导入（含警告行、错误行、空值行），导入预览完成且
错误/警告计数正确；耗时实测 < 8s 写入评审记录。
*为什么必须有这条*：ch.13 的边界用例与性能目标在「5000 行」上重合，
一次跑两个。

**3. 四条性能目标都有实测数字。**
冷启动、导入耗时、100 封队列内存、交互响应的**实测值**逐条写进评审记录，
并对照 ch.13 的目标值（< 2s / < 8s / 无增长 / < 100ms）。
*为什么必须有这条*：「性能良好」不在本项目的词表里（docs/README §3），
目标必须变成「实测 N vs 目标 M」。

**4. 门禁十项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。

**5. 不破坏发布链。**
`scripts/release.sh` 仍能产出 dmg + 校验和 + 发布记录
（本卡的改动只碰 Rust 解析与测试，不碰打包）。

**标准 1 已验（2026-11-12）**：

`cargo test fullwidth` → 3 passed：
- `util::tests::fullwidth_amount_chars_become_halfwidth_and_nothing_else` ok
- `domain::import::tests::fullwidth_amounts_parse_like_halfwidth` ok
  （`１８５００`→18500、`１８，０００．５０`→18000.5、`－２１００`→-2100、
  `＋１８０００`→+18000、`１２．５％`→12.5%、`（１８０００）`依旧报错）
- `domain::record::tests::fullwidth_cell_values_evaluate_like_halfwidth` ok
  （求值那条路：`１８５００`/`３２００`/`－２１００` → 实发 19600.00，两个汇总正确）

**实现说明**：`normalize_fullwidth` 只转五类（数字/小数点/加减/百分号），
其余原样留下 —— 半角化过头会把「（」变成「(」这类无关字符悄悄改掉。
`domain::record::evaluate_row` 与 `infra::records::period_totals` 之前对「3,200」这类
带千分位的串本来就不认，本卡**不扩大**它们的宽容度，只让全角等于半角。
