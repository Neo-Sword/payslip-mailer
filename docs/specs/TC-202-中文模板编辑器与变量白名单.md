# TC-202 · 中文邮件模板编辑器 + 变量白名单

状态：accepted · 依赖：TC-100（SQLCipher 库）、TC-200（工资条项目）、TC-201（成员名单） · 最后更新：2026-11-11

设计依据：设计文档 **ch.12 界面原型** 的 S10「中文邮件模板编辑器」
（变量插入 + 实时预览；「变量随 S04 字段配置动态生成；未知变量或空值将在发送前被拦截」；
变量面板 `{{姓名}} {{工号}} {{年月}} {{公司名称}} {{组名}} {{字段.基本工资}} {{应发合计}}
{{扣款合计}} {{实发工资}} {{工资条表格}}`；「右预览默认用『第一位成员』渲染」；
「未解析变量高亮并阻止设为默认」；「试发给自己」不写入正式发送日志；
渲染由 minijinja 沙箱执行）；**ch.10 中文模板示例**（模板正文原文与
「同时自动生成 text/plain 兜底版本……HTML 内联 CSS，中文字体栈 PingFang SC, Microsoft YaHei, sans-serif」）；
**ch.10 防错机制**第三条（变量完整：所有变量必须能解析且非空；缺失字段直接拦截，
绝不发出「{{实发工资}}」字面量）；**ch.6** 的 `email_templates` 表定义；
**ch.9** 的错误提示三要素；**ch.4** 红线 4（模板引擎沙箱化，禁止文件读取 / 系统调用 / 访问环境变量）。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：ADR-0017（本卡十条口径：**minijinja 且不开 `loader`**、未知变量报错并阻止设为默认、
**字段变量用 key 不用显示名**、两份白名单、**空值按「是否必填」判定**、
**试发不做**（要 SMTP）、text/plain 兜底自动生成、HTML 内联 CSS + 中文字体栈、
预览用示例数据、初始化写入设计文档的默认模板）；
ADR-0004（错误词表先行）；红线 4。

## 目标

做完之后使用者能干什么：

- **配一份自己的中文工资条模板**：左边写正文，右边实时预览「张三收到的那封信长什么样」。
- **变量点一下就插入**，且**插入的一定是可用的**（面板里的变量就是白名单）。
- **写错变量名当场就被拦下**：模板里写了一个不存在的变量 → 高亮 + 不让设为默认，
  绝不会把「{{实发工资}}」这样的字面量发给员工。
- **换个人也能用同一份模板**：变量按字段的 key 引用，改个显示名不会让老模板坏掉。

## 范围

**做**：

1. 迁移 `0005_email_templates.sql`：`email_templates` 表（设计文档 ch.6：
   id / name / subject_tpl / body_html / body_text / is_default）。
2. `domain/template.rs`：模板的纯逻辑 ——
   **变量白名单**（内置变量 + 字段变量）、**变量解析**（模板里有哪些变量）、
   **未知变量检查**、**text/plain 兜底生成**、**HTML 表格渲染**（`{{工资条表格}}`）。
3. `infra/templates.rs`：模板的读写（列出 / 新建 / 编辑 / 存副本 / 设为默认 / 删除）。
4. `commands/templates.rs`：`list_templates` / `create_template` / `update_template` /
   `duplicate_template` / `set_default_template` / `delete_template` /
   `template_variables`（白名单，给变量面板）/ `preview_template`（用示例数据渲染）。
5. 渲染引擎：**minijinja 3.1**，`default-features = false` +
   `features = ["builtins", "debug", "serde", "unicode"]`，
   **不开 `loader`**（红线 4：结构上没有读文件的路）。
6. S10 界面：模板列表（2 个 / 默认的那个）+ 左侧编辑（主题 + 正文 HTML）+ 右侧实时预览 +
   变量面板（点一下插入光标处）+ 底部状态（「变量全部可解析 · 已自动生成 text/plain 兜底版本」）。
7. **初始化时写入默认模板**（设计文档 S10 的「标准中文模板」，正文取设计文档 ch.10 的原文）。
8. `error.rs` 加模板相关的错误码（按 ADR-0004 词表先行）。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **「试发给自己」真的发一封** → **TC-500**（要真实 SMTP 账号，现在 blocked）。
  本卡把按钮位置留着，文案说清「需要先在设置里配置发件邮箱」。
  「试发不写入正式发送日志」那条属于发送侧（TC-402/403 的 `send_jobs` 表）。
- **模板的导入/导出**（从别的系统搬模板）→ 不做。
- **模板的多语言版本**（一份模板配多套语言）→ 不做。
- **在模板里写条件判断**（如「扣款 > 0 才显示某段」）→ 不做。
  minijinja 的条件语法技术上可用，但那时要重新审一遍沙箱口径（ADR-0017 后果段）。
- **用真实工资数据预览** → TC-303（真实数据在那时才存在）。本卡用**示例数据**，
  界面上明确标明。
- **模板版本历史**（改坏了能回退）→ 不做。要回退就「存为副本」（设计文档的按钮）。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 首启后有设计文档的那个默认模板。**
新建一个库 → `list_templates` 返回 1 个模板「标准中文模板」，`is_default == true`，
正文里含 `{{姓名}}`、`{{年月}}`、`{{工资条表格}}`、`{{实发工资}}`、`{{回信邮箱}}`。
*为什么必须有这条*：设计文档 S01 明写「初始化成功后写入 admins、Keychain 与
**默认字段模板**」，TC-200 交付了默认字段集，这一半是同一句话的另一半。
正文取自设计文档 ch.10 的原文，不是我们自己编的文案。

**2. 变量面板里的变量全部来自白名单，且与 S04 的字段动态联动。**
`template_variables` 返回：内置变量（姓名/工号/年月/公司名称/组名/回信邮箱/
应发合计/扣款合计/实发工资/工资条表格）+ 每个**未停用**的字段（以 key 出现、显示名可读）。
停用一个字段后 → 它从面板里消失。
*为什么必须有这条*：设计文档 S10 原话「变量随 S04 字段配置动态生成」。
面板是使用者唯一能拿到「合法变量」的地方 —— 面板之外的变量都要被拦。

**3. 模板里的未知变量 → 渲染报错 + 不让设为默认。**
模板正文写 `{{字段.nosuchfield}}` → 校验报「未解析的变量：nosuchfield」，
`set_default_template` 被拒；界面把它高亮。
*为什么必须有这条*：设计文档 S10 交互要点「未解析变量高亮并阻止设为默认」，
以及 ch.10 防错机制③「绝不发出「{{实发工资}}」字面量」——
这是「发错工资条」与「发出去一封带占位符的邮件」的防线。

**4. 「停用的字段」仍能被历史模板渲染。**
停用一个字段 → 它不在变量面板里（新模板不能用），
但**已存在的模板**里如果还有它 → 渲染仍然成功（用示例数据里的值）。
*为什么必须有这条*：红线 8 的另一面。字段停用只影响**新**数据；
上个月的模板渲染的是上个月的数据，它引用的那个字段必须还能认。

**5. 变量用 key，改显示名不会让老模板坏掉。**
把字段「基本工资」的显示名改成「底薪」→ 老模板（引用 `{{字段.base_salary}}`）仍能渲染；
变量面板里显示的是「底薪」但插入的仍是 `base_salary`。
*为什么必须有这条*：用显示名引用的话，HR 改个名会让所有老模板同时失效，
而失效信息（未解析变量）根本不会告诉他「是你改的名」。

**6. 渲染器的沙箱是结构性的：没有读文件的能力。**
`grep -n 'loader' src-tauri/Cargo.toml` 命中 0 次（minijinja 的 `loader` feature 没开）；
渲染一个 `{% include %}` 或 `{{ open('/etc/passwd') }}` 之类的模板 → 报错，不是读到文件。
*为什么必须有这条*：红线 4「模板引擎沙箱化，禁止文件读取 / 系统调用 / 访问环境变量」。
「结构上没有那个能力」比「我们记得别用它」可靠得多。

**7. text/plain 兜底自动生成。**
保存一个含 `{{工资条表格}}` 的模板 → `body_text` 里有一份**纯文本**的表格
（列名与数值对齐），不是 HTML 标签。
*为什么必须有这条*：设计文档 ch.10 原文「同时自动生成 text/plain 兜底版本（表格转纯文本对齐），
避免部分客户端把纯 HTML 邮件判为垃圾邮件」。

**8. HTML 内联 CSS + 中文字体栈。**
生成的工资条表格里带内联样式，且字体栈是 `PingFang SC, Microsoft YaHei, sans-serif`。
*为什么必须有这条*：设计文档原文。邮件客户端普遍不支持外部 CSS —— 内联是唯一可靠的做法；
中文字体栈缺了就是一堆方框。

**9. 空值按「是否必填」判定，不是照字面一律拦。**
必填字段（如默认集里的「基本工资」）值为空 → **发送前被拦下**；
可选字段（如「工号」）值为空 → **不拦**。
*为什么必须有这条*：工号在成员表里就是可选的（ch.6）。照字面「非空」执行，
一个没填工号的成员会永远收不到信。

**10. 预览用示例数据，且界面上标明。**
`preview_template` 返回渲染后的 HTML 与纯文本两版；
预览区标题标明「示例数据」。
*为什么必须有这条*：设计文档 S10「右预览默认用『第一位成员』渲染」——
真实工资数据在 TC-303 才有。用示例数据时**必须说清是示例**，
否则使用者会以为看到的是真人的工资。

**11. 模板能「存为副本」。**
复制「标准中文模板」→ 多出一个副本，改副本不影响原模板。
*为什么必须有这条*：设计文档 S10 的「存为副本」按钮。
它是「改坏了能退」的唯一手段（本卡不做版本历史）。

**12. 门禁九项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。九项按名字：Rust 格式、
前端类型检查、设计 Token（色值只允许出现在 `tokens.css`）、Token 引用可解析、
敏感数据未进 git、Rust 静态检查（clippy `-D warnings`）、Rust 单测、
加密栈链接（`otool`：链 `Security.framework`、零 `libcrypto`/`libssl`）、前端构建。
*为什么必须有这条*：本卡第一次引入**模板引擎**——它是唯一能执行「用户写的表达式」
的地方。门禁与单测是它唯一的护栏。

### 二、实现期当场改掉的三个问题

1. **变量面板忘了按「未停用」过滤** —— 被测试抓到（停用的字段混进了面板）。
   已修（`domain/template.rs` 的 `variable_panel`）。
2. **金额没带千分位** —— 设计文档 S10 的预览写的是「本月实发：**¥16,840.00**」。
   已加 `domain::template::format_amount`（千分位 + 两位小数），
   **格式化放在取值那一层**，模板不做格式化（模板不该知道「这个变量是钱」）。
3. **预览不能用 `dangerouslySetInnerHTML`** —— 模板里可能有 `<script>`，
   直接注入会让它在 webview 里执行，而 webview 有 Tauri 的能力（`dialog:allow-open` 等）。
   已改成 **`<iframe sandbox="">`**：脚本被禁，与邮件客户端的行为一致。

### 三、实现期的两个依赖决定

- **minijinja 3.1**，`default-features = false` + `features = ["builtins", "debug", "serde", "unicode"]`。
  **不开 `loader`** —— 那是「从文件加载模板」的开关，不开它，「从磁盘读模板」这条路
  在**结构上**就不存在（红线 4：沙箱不靠约定，靠没开那个开关）。
- `unicode` 是为了让**中文变量名**能解析（不开它 minijinja 只认 ASCII 标识符，
  `{{姓名}}` 直接报 `syntax error`，实测）。依赖代价：**只多 `unicase` 一个纯 Rust crate**。

### 四、结论

- **12 / 12 条已过**，无豁免项，本卡结案：`状态` 转 accepted、ADR-0017 转 accepted、TASKBOARD 更新。
- **「试发给自己」没做**（要真实 SMTP → TC-500，现在 blocked）——
  界面上的按钮位置留着，文案说清「需要先在设置里配置发件邮箱」。
- **预览用示例数据**，真实数据到位（TC-303）后要换成真数据 —— 那是换数据源，不改渲染逻辑。
