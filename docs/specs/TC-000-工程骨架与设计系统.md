# TC-000 · 工程骨架与设计系统

状态：accepted（2026-11-11 验收，见评审记录）
依赖：无（P0 起点）
设计依据：设计文档 ch.4（分层）· ch.12 S15（错误码三要素）· 原型 S01–S15 视觉规范 ·
ADR-0001 技术栈 / 0002 未签名分发 / 0003 SDKROOT / 0004 错误词表 / 0005 Token 体系 / 0006 npm 镜像 / 0007 Tauri 版本 / 0008 dmg 产出

## 目标

一条命令能从干净 clone 起出可运行界面与可分发 dmg；颜色与错误口径各自只有一个来源，
从 P1 起的每张卡不必再讨论「这个颜色从哪来」「这个错误该怎么说」。

## 范围

**做**：Tauri 2 + React/TS 骨架与三层目录约定（commands / domain / infra）、
Design Token 与组件库基线（按钮 / 输入 / 开关 / 卡片 / 表格 / 进度 / 步骤 / 模态 / toast / 侧边栏外壳）、
统一错误码与序列化契约、验收门禁脚本、发布脚本、CI。

**不做**：任何业务逻辑（无数据库、无 Excel、无 SMTP、无模板引擎）；
不做浅色主题切换；不做 PDF 附件（决策 D1）；不做自动更新；不做 i18n；不做 Windows。

界面此刻是**静态 mock 数据**，用来验证组件与 Token，不是功能实现。

## 验收标准

每条都可证伪：能跑一条命令，或能在界面上看到确定结果。

1. **门禁全绿**：`bash scripts/gate.sh` 退出码 0，且输出含 8 项检查
   （Rust 格式 / 前端类型 / 设计 Token / Token 可解析 / 敏感数据 / clippy / Rust 单测 / 前端构建）。
2. **门禁真的会拦（反向验证）**：分别注入「组件层一个裸色值」「一个拼错的 `var(--x)`」
   「版本库里一个 `members.csv`」，三次 `gate.sh --fast` 必须各自退出码 1 且指名违规位置；
   撤掉注入后必须恢复 0。
   *为什么必须有这条*：空仓库时敏感数据检查是**空跑**，只跑正向一遍等于没验收。
3. **色值单一来源**：`grep -RIn -E '#[0-9a-fA-F]{3,8}' src`（排除 `src/styles/tokens.css`）命中 0 行。
   扫描范围必须是整个 `src`，不是某个子目录。
4. **Token 引用可解析**：`src` 下每个 `var(--x)` 都能在 tokens.css / global.css 找到声明。
5. **错误契约**：Rust 单测覆盖「错误序列化为 `{code, message}`，管线类错误
   （Internal / Database / Keychain / Io）不把内部细节带进前端」，
   且「业务类错误保留用户可理解的细节」。
6. **状态机先行**：账套状态机的「草稿可编辑 / 发送中与已发送不可编辑 / 跳级被拒」有单测且通过。
7. **可分发产物**：`bash scripts/release.sh` 在**无 GUI 会话**（后台任务）里退出码 0，
   产出 dmg 与 `.sha256`；`lipo -archs` 同时含 `arm64` 与 `x86_64`；
   `shasum -a 256 -c` 通过；`spctl -a` 拒绝且原因含 `no usable signature`（未签名预期，见 ADR-0002）。
8. **产物不被误删**：dmg 不在 vite 的输出目录 `dist/` 里（否则下一次 `npm run build` 会清空它）。
9. **CI 与本地同一份「绿」**：CI 的 check job 调用 `bash scripts/gate.sh`，
   不自行罗列检查项；上传路径与实际产物目录一致。
10. **界面目视**：起界面后深色主题、侧边栏与组件展示区**没有无色空白块**
    （无色空白 = 未解析的 `var()`，见 ADR-0005），窗口标题「薪邮」，红绿灯位置符合配置。

## 评审记录

验收日期：2026-11-11 · 结论：**通过**（标准 10 的一部分豁免，见末尾）

以下每条写的是**实际观察到的输出**，不是「已验证」。

**1. 门禁全绿** —— `bash scripts/gate.sh` 退出码 0，日志 `/tmp/gate-full.log`。
实际输出 **8** 项检查（本条原写「7 项」是笔误，已改），逐项 ✓，末行「✓ 门禁全绿」。

**2. 门禁真的会拦** —— 三次注入各自退出码 1 且指名位置，撤掉后恢复 0：

| 注入 | 门禁实际输出 |
|---|---|
| `controls.module.css:264` 加 `.probe{color:#123456}` | 指名该行，要求改 `var(--token)` 或加 `no-token` 豁免 |
| 同文件加 `var(--nope-missing)` | `controls.module.css:264 未声明的 --nope-missing` |
| `git add test-data/members.csv` | 「以下含个人信息的文件已进 git：test-data/members.csv」 |

*这条不是走过场*：验收时仓库**零 commit**，敏感数据检查正向跑是空跑，不注入等于没验收。

**3. 色值单一来源** —— `grep -RIn -E '#[0-9a-fA-F]{3,8}' src`（排除 tokens.css 与 `no-token` 豁免行）
命中 **0** 行，扫描范围是整个 `src`。
验收中抓到并修掉的真实漏网：`App.tsx:95` 内联 `#a8bad6`、`global.css:80/86` 滚动条 `#333d50` / `#45516a`。
原因是扫描只覆盖 `src/components`——**门禁全绿而规矩没守住**，故扫描范围本身也被改成「整个 src，只放行 tokens.css」。
滚动条两色没有就近并入数值相同的 `--line`，而是新建 `--scroll-thumb` / `--scroll-thumb-hover`：数值巧合 ≠ 角色相同（ADR-0005）。

**4. Token 引用可解析** —— 门禁第 4 项 ✓；`tokens.css` 现有 **120** 条声明（ADR-0005 原记 118，已同步）。

**5. 错误契约** —— `cargo test` 输出 `test result: ok. 9 passed; 0 failed`，其中
`error::tests::error_serializes_to_stable_code_and_chinese_message`、
`plumbing_errors_never_leak_internal_details_to_the_frontend`、
`message_states_what_happened_impact_and_next_step` 三条覆盖本条。

**6. 状态机先行** —— `domain::period::tests` 三条（草稿可编辑 / 发送中与已发送不可编辑 / 跳级被拒）在同一批 9 passed 内。

**7. 可分发产物** —— `bash scripts/release.sh` 在**后台任务**（无 GUI 会话）退出码 0；
`artifacts/薪邮-0.1.0.dmg` 4.7 MB；`shasum -a 256 -c` → `薪邮-0.1.0.dmg: OK`；
`lipo -archs` → `x86_64 arm64`；`spctl -a -vv` → `rejected`，`source=no usable signature`（未签名预期，ADR-0002）。

**8. 产物不被误删** —— dmg 落在 `artifacts/`，不在 vite 的 `dist/`；`.gitignore` 已含 `artifacts`。

**9. CI 与本地同一份绿** —— `.github/workflows/release.yml` 的 check job 调 `bash scripts/gate.sh`，
不再自行罗列检查项（旧写法漏了 Token 两条红线与敏感数据检查）；上传路径 `artifacts/*` 与产物目录一致。

**10. 界面目视** —— **部分豁免**。

已证（web 产物）：`dist/` 用无头 Chrome 以 1200×800 渲染截图 `/tmp/p0-shot.png`——
深色主题、侧边栏五个分组、统计块 / 卡片 / 步骤条 / 表格 / Chip / 进度条**全部有色，没有无色空白块**；
应用自绘标题栏居中显示「薪邮」。

已证（配置层）：`tauri.conf.json` 窗口 `title: "薪邮"`、`hiddenTitle: true`、`titleBarStyle: "Overlay"`、
`trafficLightPosition {x:12, y:13}`、`theme: "Dark"`；`AppShell.tsx:82` 用 `isTauri()` 守卫——
浏览器预览画仿制红绿灯，Tauri 内让位给原生，不会同时出现两套。

附带证据（能编译 ≠ 能启动）：直接执行 `薪邮.app/Contents/MacOS/payslip-mailer`，
进程存活 6 秒以上、stderr 无输出。

未证：**原生窗口的像素截图**（红绿灯的实际位置）。从后台 shell 起 app 时 System Events 看不到它的窗口，
与 ADR-0008 记的是同一类「依赖 GUI 会话」的问题。
