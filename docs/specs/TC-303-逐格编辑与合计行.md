# TC-303 · 逐格编辑 + 公式列重算 + 合计行

状态：**accepted** · 依赖：TC-203（公式求值器）、TC-300（月份账套）、TC-302（salary_records 表 + 导入） · 最后更新：2026-11-12

设计依据：设计文档 **ch.12 界面原型** 的 S07「月度工资数据」
（「金额可双击编辑并自动重算公式列」「公式列由系统计算，不可直接编辑」
「共 42 条记录 · 校验通过 41 · 待处理 1」「赵六那行『个税』是『—』，
『实发工资』照样算出 13,100.00（校验列标『个税缺失』）」
「本页合计　应发 / 扣款 / 实发」「有校验警告时『前往预览核对』仍可点，
但 S11 会拦截该成员进入发送范围」）、
**ch.6**（`salary_records` 的 `values_json / checksum / source`）、
**ch.5** 状态机（「发送中/已发送状态禁止编辑工资数值」）。

> **引用口径**：本卡引用设计文档一律用**章号 + 屏号 / 章标题**，不写行号。

决策依据：ADR-0022（本卡八条口径：**单格保存**、**行求值走唯一权威**、
**校验列 = 必填缺失警告（拦发送不拦保存）**、**表级合计 = 整月**、
**编辑权 Command 层再查一次**、**逐格编辑不写 audit**、**保存后整行重算 checksum**、
**整行删除**）。

## 目标

做完之后使用者能干什么：

- **在表格里直接改数**：双击一格 → 改 → 保存 → 公式列（实发工资）当场重算。
- **一眼看出哪行有问题**：校验列标「通过 / 个税缺失」；表头有「校验通过 N · 待处理 M」。
- **看得懂整月的钱**：表底合计行给出整月的应发 / 扣款 / 实发。
- **给错的人能撤掉**：删掉整行记录（editable 状态下）。

## 范围

**做**：

1. `infra/records.rs`：工资记录的读写 —— 列出某月的全部记录（拼上成员姓名邮箱）、
   单格更新（整行重算公式列 + checksum）、整行删除、整月合计。
2. Command：`list_records`、`update_record_cell`、`delete_record`、`get_period_totals`。
3. S07 表格本体：接进 PeriodPanel —— 表格（固定列 + 当月列）、
   金额单元格编辑（失焦保存）、公式列只读、校验列、合计行、记录数统计。
4. 删除整行的确认对话框。

**不做**（范围膨胀是本项目最大的风险，逐条写清归属）：

- **分页** → v1 不做（42 人一屏放得下，表格规范用横向滚动）。
  「本页合计」= 整月合计（ADR-0022 决策 4）。
- **自动保存 / 防抖** → 显式保存（失焦/回车）。ADR-0022 洞一。
- **格级修订留痕** → v2（ADR-0022 洞四）。
- **发送范围过滤**（校验警告的行在 S11 被拦）→ TC-401。
- **批量粘贴进表格**（TSV 粘贴多格）→ v2；S08 的导入已经覆盖批量场景。
- **「前往预览核对」按钮的跳转** → TC-401（S11 还没建）。

## 验收标准

每条都要在验收时给出**实际观察到的输出**，不接受「已验证」。

**1. 列出某月的记录：有人的行 + 有值。**
导入（或造）3 条记录 → `list_records` 返回 3 行，每行带成员姓名、邮箱、
各字段值；公式列的值是**库里存的**（导入时算好的）。
*为什么必须有这条*：表格是这一屏的本体；没有它其余都谈不上。

**2. 没有记录的月份 → 空表格 + 明确的空状态。**
新建一个空账套 → 表格显示「这个月还没有工资数据」与一个指去导入/导出的提示，
**不是**一张只有表头的死表。
*为什么必须有这条*：设计文档 ch.11 的空状态规范「绝不只写『暂无数据』」。

**3. 单格保存：改一格 → 公式列当场重算。**
把张三的基本工资 18000 改成 20000 → 返回的行里 `net_pay` 从 17700.00
变成 **19700.00**；库里 `values_json` 的 `base_salary` 是新值、
`net_pay` 是重算值。
*为什么必须有这条*：S07「金额可双击编辑并自动重算公式列」。

**4. 公式列不可编辑。**
界面上公式列的单元格没有编辑入口；后端 `update_record_cell` 对公式列
返回错误。
*为什么必须有这条*：S07「公式列由系统计算，不可直接编辑」。
前端禁用 + 后端拒绝，两层都要有（Command 层是唯一关卡，红线 5 的同族）。

**5. 公式算不出来 → 拒绝保存，旧值保留。**
把一行改成让公式除零（扣款合计为 0 时 `base_salary / 扣款合计` 类公式）→
保存被拒、错误说清原因、库里还是旧值。
*为什么必须有这条*：ADR-0022 决策 2。静默存一个坏值，
TC-401 的内容核对就会拿它当真的。

**6. 校验列：必填缺失 → 警告；其余 → 通过。**
删掉张三的「基本工资」（必填）→ 校验列显示「基本工资缺失」，
表头统计「待处理 +1」；**保存仍然成功**（警告不拦编辑）。
*为什么必须有这条*：S07 的「个税缺失」与「校验通过 41 · 待处理 1」。
拦截发送归 TC-401（S07 原型明写「S11 会拦截该成员进入发送范围」）。

**7. 表级合计 = 整月，公式列不进合计。**
两行：A 行 18000/-2100、B 行 15000/-1750 → 合计行显示
应发 33000.00、扣款 -3850.00、实发 29150.00；
实发**不是**把两行的 `net_pay` 再加一遍（那会重复计公式列）。
*为什么必须有这条*：S07 表底的「本页合计」；ADR-0022 决策 4。

**8. 编辑权在 Command 层再查一次。**
把账套推到 `sending` → `update_record_cell` 返回错误（不是前端装死）；
推回 `draft` 后又能改。
*为什么必须有这条*：ch.5「发送中/已发送状态禁止编辑工资数值」；
TC-300 的 `editable` 是前端提示，Command 层的检查才是关卡。

**9. 删除整行：确认后删，且只删那行。**
删除张三这行 → 库里剩 2 条记录；李四、王五的记录完好。
*为什么必须有这条*：ADR-0022 决策 8「给错了人要撤掉」。

**10. 保存后 checksum 被整行重算。**
改一格 → `salary_records.checksum` 等于
`record::checksum(邮箱, 新 values_json)`。
*为什么必须有这条*：checksum 是 TC-401「内容一致」核对的基础 ——
存的是旧值的话，发送前的比对会拿没改过的内容当真的。

**11. 逐格编辑不写 audit_log。**
连改 3 格 → `audit_log` 里**没有**新增的记录行。
*为什么必须有这条*：ADR-0022 决策 6 —— 审计粒度是成批动作，
格级留痕会把审计日志淹没。

**12. 单格保存只动那一行。**
改张三的格 → 李四的 `values_json` 与 `checksum` **逐字节不变**。
*为什么必须有这条*：单格保存的「单」必须是真的 ——
一次全表重写会顺手把别人的行也动掉（哪怕内容没变，`updated_at` 变了）。

**13. 门禁九项全绿。**
`FAST=0 bash scripts/gate.sh` → 「✓ 门禁全绿」。九项按名字：Rust 格式、
前端类型检查、设计 Token、Token 引用可解析、敏感数据未进 git、
Rust 静态检查（clippy `-D warnings`）、Rust 单测、加密栈链接、前端构建。
*为什么必须有这条*：本卡第一次在表格里编辑工资数值，
「敏感数据未进 git」与「设计 Token」两项持续被压测。

**验收时发现并当场修的问题**

1. **测试基座 `seed` 没走值的规范化**：造数直接存 `"18000"`，而真实导入路径存 `"18000.00"`。
   那会让「标准 5 的旧值保留」断言对不上库里的真实形态。已让 seed 走与导入同样的
   `parse_amount → "{n:.2}"` 规范化 —— 测试造的数与生产路径写的数**同构**。
2. **合计期望值算错**（38900 → 39000）：测试自己的算术错，实现无误。

**实现口径的说明**

- **编辑入口**：v1 用「点击单元格进入编辑框」（S07 原型说「双击」—— 单击对触控板更友好，
  行为语义一致：点格子 → 改 → 失焦/回车保存）。Aria 与 title 都标了「点击编辑」。
- **公式列在合计行显示「实发」**：合计行没有在公式列那格显示重复数字，
  实发只出现在表底的合计条（应发 / 扣款 / 实发三项）——
  tfoot 里不再重复渲染（走查确认）。
- **「前往预览核对 →」按钮仍是 disabled**（TC-300 留下的占位）：S11 还没建（TC-401），
  本卡范围明确不含跳转。

**要认的账（本卡遗留的边界，不是缺陷）**

- **界面交互（点击编辑、删行确认）只做了走查**，浏览器预览模式下结构正确；
  真机点击链与 TC-103/104/302 的待验证项一起归使用者。
- **「本页合计」= 整月合计**（v1 无分页，ADR-0022 决策 4）；分页时要改成真正的本页。
- **S07 原型的「筛选」与「切换月份 ▾」下拉**：切换月份已就位；筛选（按校验状态过滤行）
  是纯前端便利功能，v2 再做。
