# ADR-0006 · npm 镜像源不写进仓库

日期：2026-11-11 · 状态：accepted

## 背景

本机 `npm install` 曾很慢，用国内镜像（npmmirror）能明显加速。
直觉做法是把 `registry=https://registry.npmmirror.com` 写进仓库的 `.npmrc`，一劳永逸。

**事实核对**：仓库里的 `payslip-mailer/.npmrc` 目前是**空文件** —— 加速靠的是本机全局
`~/.npmrc`，从来没有进过仓库。所以这不是「要不要改策略」，而是「要不要补一个从未存在的约定」。

## 决策

**不入库**。仓库不规定 registry，镜像是每台机器的网络环境属性，不是项目属性。

## 理由

- CI 与海外网络访问 npmmirror 反而更慢甚至不通；把镜像钉进仓库等于让 CI 依赖一个国内服务。
- 一旦入库，换网络的人要**先删配置**才能装，比缺配置更隐蔽（报错是超时，不是「没配镜像」）。
- 空文件留在仓库里反而误导：看着像「有 npmrc 配置」，实际什么都没有。

## 后果

- 新机器 clone 后首次 `npm install` 可能很慢，属预期，不是故障。
- 需要加速的人自己执行 `npm config set registry https://registry.npmmirror.com`；
  文档里给这一行作为**可选**提示，脚本不自动改使用者的全局配置。
- 版本可复现性靠 `package-lock.json`，与 registry 无关 —— 这是本决策成立的前提。

## 顺手清理

把空的 `payslip-mailer/.npmrc` 删掉，避免「看起来有配置」。
**已于 2026-11-11 执行**（TC-000 验收时核对：文件已不存在）。

## 重新评估的触发条件

- 团队固定在同一内网、CI 也走同一出口 → 再入库，并同时提交 lockfile 校验。
- 若公司内网有私有 registry（审计要求）→ 那是新决策，另写 ADR，不在这里追加。
