# ADR-0001 · 技术栈：Tauri 2 + Rust + React/TS

日期：2026-11-11 · 状态：accepted

## 背景

使用者是 100–500 人公司的 HR，一台自己的 Mac 上跑，工资数据**不能出本机**
（设计文档 ch.2 隐私红线）。要读写 Excel、要连 SMTP、要把数据库密钥放进
macOS 钥匙串、要加密存储。交付物是一个 dmg，不是网页。

## 决策

**Tauri 2**（WKWebView 渲染前端 + Rust 承担全部业务与 I/O），前端 **React 19 + TypeScript**，
数据层 **SQLCipher**（SQLite + 全库加密），样式 **CSS Modules + Design Token**。

## 为什么不是别的

| 备选 | 放弃原因 |
|---|---|
| Electron | 多带一个完整 Chromium（安装包 ~150MB 起）。本项目界面只有十几个屏，体积与内存代价换不来任何能力。 |
| 原生 Swift/SwiftUI | 体积与体验最优，但 Excel 解析、模板引擎、公式求值都要重造，且现有 HTML 原型（`payslip-mailer-design.html`）无法复用。 |
| Python + pywebview | 打包体积与启动体验差，且 HR 机器上没有 Python 环境的假设不成立；PyInstaller 产物在未签名分发下更难放行。 |
| 纯网页 + 后端服务 | 直接违反「数据不出本机」。 |

## 关键后果

1. **前端拿不到工资数值与凭据**，所有外部副作用必须经 Rust Command 层。
   这不是性能考虑，是权限边界：JS 侧一旦被注入，能读到的东西就是它的上限。
2. Rust 侧承担 Excel（`calamine` / `rust_xlsxwriter`）、模板、SMTP、加密全部逻辑，
   因此**每个 Command 都是天然的单元测试边界**，这是本项目测试策略的地基。
3. 版本耦合：npm 侧 `@tauri-apps/api` 与 Rust 侧 `tauri` 必须 major/minor 对齐，
   否则 `tauri build` 直接拒绝构建。处置见 [ADR-0007](0007-tauri版本对齐策略.md)。
4. 前端框架选 React 而非 Vue/Svelte：原型是手写 HTML + 原生 JS，
   组件拆分粒度按 React 的组件模型映射最省事；且 `@tauri-apps/api` 官方示例即 React。

## 重新评估的触发条件

- 需要 Windows 版且 HR 愿意换机器 → Tauri 同样覆盖，无需换栈。
- 若某 Excel 库在 Rust 生态长期缺能力 → 只替换该库，不动栈。
