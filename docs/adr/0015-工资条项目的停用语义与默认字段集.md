# ADR-0015 · 工资条项目：停用即「不进新表头」、没有删除操作、默认字段集用设计文档的示例集

日期：2026-11-11 · 状态：accepted（TC-200 验收通过，评审记录见该 spec 文末）

## 背景

TC-200 做 S04「工资条项目配置」——设计文档 ch.12 写它是「**单一事实源：决定 Excel 表头 / 表格列 / 模板变量**」。

它同时要兑现两件事：设计文档 ch.6 表定义里的 `salary_fields` 表，和设计文档 S01
那句「初始化成功后写入 admins、Keychain 与**默认字段模板**」（TC-103 当时明确把这项后置到本卡）。

有三个洞必须在写代码前堵上。

### 洞一：「停用」在表里是哪一列？

设计文档 ch.6 的 `salary_fields` 是这样写的：

> `salary_fields | id, key, label, data_type, sort_order, required, visible, formula, align | data_type ∈ text/number/money/percent/formula | 停用不删；影响模板表头与变量白名单`

**9 列里没有独立的 `active`**（对比一下：`members` 表明确有 `active`）。
而 S04 的表单说明写的是：

> 已被历史月份引用的字段不能删除，只能「停用」。**停用后不再出现在新导出的 Excel 模板中，历史数据保持原样。**

⇒ 「停用」= **不再出现在新导出的表头里** = `visible = 0`。
这与 9 列的表定义完全吻合：`visible` 一个列同时承担「不进新表头」与「不在变量白名单里」，
正是设计文档说的「影响模板表头与变量白名单」。

**但有一个坑必须在这里说清**：停用的字段**不能**从「可用的模板变量」名单里彻底消失，
否则**上个月的模板会因为字段被停用而渲染不出来**（历史数据里那个字段的值还在）。
⇒ 变量白名单要分两份：**新建模板时可选**（只含 visible 的）与
**渲染历史模板时要认**（含已停用的）。这条在 TC-202 才用得上，但决定在今天。

### 洞二：删除操作到底给不给？

S04 的原型里，操作列只有「编辑」；但表单说明写「已被历史月份引用的字段**不能**删除」——
这句话反过来暗示：**没被引用的字段是可以删的**。

问题在于 TC-200 的时候 `salary_periods`（月份账套）还不存在（那是 TC-300），
**「有没有被历史引用」这个判据根本无从谈起**。

本卡的选择：**只给「停用 / 启用」，不给删除**。

理由不是「将来不好加」，而是：

- 红线 8 的口径是「字段一旦被历史数据引用**只能停用不能删除**」。
  在还没有历史数据的此刻，把删除开出来，等于给「误删一个刚建错的字段」开一条路，
  而这条路的收益（少一个字段）远小于它的代价（整列数据不可逆地丢）。
- 设计文档原型自己的操作列也没有删除。
- 将来真要删除，判据（`salary_periods.field_snapshot` 里有没有引用这个 key）
  到 TC-300 才有 —— 那时候加，是一个有判据的独立决定，不是今天顺手开的口子。

**⇒ 停用是唯一的「让它消失」的手段**（它不进新表头、不在新建模板的白名单里，
但历史数据里那个字段的值仍然可读、旧的模板仍然渲染得出来）。

### 洞三：默认字段集用哪一套？

TASKBOARD 的外部输入表把「真实工资条字段清单与公式口径」列为 TC-200/203/301/302 的阻塞项，
理由是「字段一旦被历史数据引用只能停用不能删除，**现在定错，以后一直背着**」。

本卡重新读了设计文档 ch.12 的 S04 原型，发现两件事：

1. **字段是用户数据，不是代码里写死的东西**。S04 就是让 HR 自己配的界面 ——
   原型里那七项（基本工资 / 绩效奖金 / 餐补 / 社保个人 / 公积金 / 实发工资 / 备注）
   是**示例数据**，不是「薪邮内置的字段清单」。
2. **现在还没有任何历史数据**。P2（字段/成员/模板）与 P3（导入/账套）都还没开始，
   没有任何月份引用过任何字段。**所以「定错就一直背着」的成本此刻是最低的**——
   错了就是一个还没被任何历史引用的字段，改掉没有代价。

⇒ **本卡写入设计文档 S04 原型的那一组作为默认字段集**，理由三条：

- 它是设计文档明确要求的（ch.6 表定义 + S01 的「默认字段模板」），
  不是我们凭空编的；
- 写进去之后 S04 立刻是个可用的界面（HR 看到一份像样的工资结构，照着改），
  而不是一堆空白行要他从零想；
- 写错了改起来此刻零成本（没有历史引用）—— 等 P3 开始导数据了再改就晚了。

**⇒ 明确记下这是本卡唯一的一处「猜」**，并且在 S04 的界面上直说：
「这是设计文档里的示例清单，请按贵司实际情况增删停用」。

### 附带：公式的校验边界

S04 的表单写「公式仅支持本行字段与 + − × ÷ ( )」，TC-203 才是求值器。

本卡做**轻量校验**（保存时就能挡住低级错）：
① 公式里引用的 key 必须都存在（拼错 key 是最常见的错）；
② 括号必须配平；
③ 只能出现「标识符 / 数字 / + − × ÷ ( ) / 空格」这些字符。

**完整的语法解析与求值留给 TC-203**（那时才知道公式语言的确切形态）。

## 决策

1. **停用 = `visible = 0`**，一个列同时管「新表头」与「新建模板的白名单」。
   渲染历史模板时的白名单是另一份（含已停用的），见洞一。
2. **只给停用/启用，没有删除操作**（洞二）。要删字段 = 停用它。
3. **默认字段集 = 设计文档 S04 原型的那七项**（洞三），写在初始化时，
   且**只在 `salary_fields` 为空时写**（不覆盖用户已有的配置）。
   界面上一句话说明「这是示例清单，按贵司实际情况调整」。
4. **key 唯一 + 格式受限**：只允许小写字母、数字、下划线；不能中文、不能空格。
   key 会进 Excel 表头与模板变量 `{{key}}`，必须跨工具安全。
5. **公式轻量校验**在保存时做（洞三附段），完整求值留给 TC-203。
6. **类型枚举**照设计文档：`text / number / money / percent / formula`。
   `formula` 类型的行才有公式；其它类型的公式字段必须为空（存了就报错）。
7. **「预览表头」= visible 的字段按 sort_order 拼出来的列** ——
   这正是设计文档 S04 说的「直接展示下一份空模板会出现的列」，
   也是 TC-301 导出表头的**唯一真相源**（TC-301 复用它，不另算一遍）。

## 后果

**变简单的**：

- 字段的唯一真相源是 `salary_fields` 一张表：表头、表格列、模板变量都从它派生
  （设计文档 ch.12 的「单一事实源」）。
- 「预览表头」与 TC-301 的导出表头共用同一个函数，不会两处算出两个答案。
- 没有删除操作 ⇒ 不需要「有没有被历史引用」的判据（TC-200 阶段它还不存在）。

**要认的账**：

- **默认字段集是我们替贵司猜的一组**。它是设计文档的示例集，不是贵司的真实清单。
  界面上一句话点明。P3 开始导数据之前改掉它没有代价。
- **停用不是删除**：停用的字段仍留在库里（历史数据要读它），只是不进新表头。
  这正是红线 8 要的语义（「只能停用不能删除」）。
- 公式只能做轻量校验，**语义对不对要到 TC-203 才验**。
  在那之前，一个括号配平但算错的公式会被存下来。

**重新评估的触发条件**：

- 若 TC-300（月份账套 + field_snapshot）落地后，确实需要「删除未被引用的字段」，
  届时加一条带判据的删除操作（判据 = field_snapshot 里有没有这个 key）。
- 若真实字段清单与示例集差异很大，TC-200 结案后可以再发一张「改默认字段集」的卡
  —— 那时改的是数据不是代码，成本一样低。

## 附：本 ADR 与其他 ADR 的关系

- **红线 8**（字段只能停用不能删除）：本卡是它在「还没有历史数据」阶段的落地方式。
- **ADR-0004**（错误词表先行）：字段相关的错误码在 `error.rs` 里按词表先行的流程加。
- **ADR-0012** §3（单位名称走 `app_meta`）：本卡的默认字段集**不走** `app_meta` ——
  它是一张有结构、有排序、要被导出的表，必须是一张表。
