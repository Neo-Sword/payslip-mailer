# ADR-0020 · 空模板导出：3 个固定列 + 启用字段，表头取账套快照，公式列留空

日期：2026-11-12 · 状态：**accepted**（TC-301 验收通过，2026-11-12）

## 背景

TC-301 做 S09「按配置导出空白 Excel 模板」。设计文档 ch.12 S09 的原型把结构写死了：

> **表头随 S04 字段配置动态生成**
> 表头预览：**3 个固定列 + 7 个启用字段 = 10 列**
> `姓名 * 邮箱 * 工号 基本工资 绩效奖金 餐补 社保个人 公积金 个税 实发工资`
> 选项：包含「填写说明」Sheet / 包含 2 行示例数据 / 预填成员名单（42 人）/ 仅导出空白表头
> 首行冻结 · 金额列数值格式 + 数据校验 · 扣款项填负数 · 「实发工资」为公式列，导入时忽略
> 导出文件名含年月便于归档

ch.8 也点了实现者：「由 rust_xlsxwriter 按 `salary_fields.sort_order` 生成」。

有四件事要定。

### 洞一：哪三列是「固定列」？

S09 说「3 个固定列 + 7 个启用字段」，S08 的表头映射又把
「姓名（固定列）/ 邮箱（固定列）/ 工号（固定列）」单列出来 ⇒
**固定列 = 姓名、邮箱、工号**，它们来自**成员表**，不是工资字段。

为什么它们要固定：工资字段是每个公司自己配的（TC-200），而
「这份表里哪几列是人、哪几列是钱」是**导入映射的锚点**——
S08 的映射规则「优先按字段 key 精确匹配，其次按显示名模糊匹配」需要一个确定的起点。
固定列锚在最前面，映射就不会因为某个工资项改了名而全乱。

### 洞二：表头取「当前配置」还是「账套快照」？

TC-300 刚做完快照（`field_snapshot`）。本卡正好撞上这个选择：

- 用**当前配置** → 「导出 9 月的空模板」导出的可能是 10 月改过的列。
- 用**快照** → 导出的正是 9 月当时的列。

TC-300 的规则已经定了（draft 用当前配置、ready 起用快照），
本卡**直接复用**它 —— 不另立一套口径（两份规则并存早晚漂移）。

### 洞三：公式列在导出的表里写什么？

S09 的原型里，「实发工资」那一列的单元格写着「**公式自动计算**」，
交互要点写「『实发工资』为公式列，导入时忽略」。

⇒ **公式列不参与导出数据**，单元格写「公式自动计算」占位。
理由有二：财务不填它（导入时也会被忽略，S08 的规则）；
而且写了数字会让人以为那是算出来的 —— 实际导入后系统会重算。

### 洞四：几个选项默认开哪个？

S09 列了四个选项（包含填写说明 Sheet / 包含 2 行示例数据 / 预填成员名单 / 仅导出空白表头）。
这是「**导出空模板**」这个功能，默认就该是空的：

- 「包含填写说明 Sheet」→ **默认开**。财务第一次拿到这张表，不知道「扣款项填负数」、
  不知道哪列是公式 —— 说明 Sheet 是最需要的。
- 「包含 2 行示例数据」→ **默认关**。示例数据混在真数据里，财务很容易忘了删，
  直接填在示例行上。
- 「预填成员名单」→ **默认关**。它要读成员表（TC-201 刚做完），而且
  预填了姓名邮箱就等于把名单带出去了 —— 用户想要的是空白表时它不该自作主张。

## 决策

1. **表头 = 3 个固定列（姓名 / 邮箱 / 工号）+ 启用字段**（按 `sort_order`）。
   固定列在前，启用字段在后（设计文档 S09 的表头预览就是这个顺序）。
2. **表头取账套的快照**：复用 TC-300 的 `display_fields`（draft 用当前配置、
   ready+ 用快照）。不另立口径。
3. **导出到 `exports/`**（设计文档 ch.6 的磁盘布局），文件名
   `薪资模板_<年月>.xlsx`（含年月便于归档，设计文档原话）。
4. **公式列不导出数据**，单元格写「公式自动计算」占位（洞三）。
5. **选项默认值**：说明 Sheet 开、示例数据关、预填名单关（洞四）。
6. **扣款项填负数**：写进说明 Sheet（设计文档原文）。这一条很要紧 ——
   填正数的社保会让实发工资算错。
7. **首行冻结 + 金额列数值格式 + 数据验证**（设计文档 S09 交互要点）。
8. **金额列的判定**：`money` / `percent` / `formula` 类型的字段是数值列，
   用 `#,##0.00` 格式；`text` 字段用文本格式；`number` 用 `#,##0.00`。
9. **导出文件里只有工资表与说明表**，没有附件、日志、成员名单（除非显式选「预填」）。
   两个 Sheet 的名字固定为「**工资表**」与「**填写说明**」——
   默认的 `Sheet1` / `Sheet2` 会让财务在两个 Sheet 之间认错（验收中发现，已修）。

## 后果

**变简单的**：

- 表头来自**一份**字段定义（账套快照），导出与导入看到的是同一套列。
- 固定列给了导入映射一个确定的锚点。
- 说明 Sheet 把「扣款填负数」「公式列不用填」这两条最容易错的事写在文件里 ——
  它跟着文件走，出了事不用回头问人。

**要认的账**：

- **导出的是「那个月的列」**，不是「现在的列」。HR 改了工资项配置后想导出**新**的表，
  得用**新的账套**（或还在草稿的当月账套）—— 这正是「历史不被改动」的代价，
  也是设计文档要的（ch.6：「防止事后改字段导致历史错位」）。
- 预填成员名单这个选项**会把名单带出文件**，所以默认关、且界面上要写明这一点。

**重新评估的触发条件**：

- 若要支持「导出多个账套到一个工作簿」→ 表头就不再是唯一的一份。
- 若要支持「模板里带公式（Excel 公式而不是占位）」→ 那就不是「公式列只读」的口径了。

## 附：本 ADR 与其他 ADR 的关系

- **ADR-0019**（快照冻结）：本卡的表头**直接复用**它，不另立口径。
- **ADR-0015**（字段是用户数据）：正因为字段随时会改，才需要按账套取列。
- **红线 2 / 数据最小化**：导出文件里没有附件、日志；预填名单是**显式选择**才有的。
