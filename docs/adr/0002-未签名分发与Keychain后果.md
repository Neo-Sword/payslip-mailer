# ADR-0002 · 不购买 Apple Developer Program：未签名内部分发

日期：2026-11-11 · 状态：accepted

## 背景

签名 + 公证需要 Apple Developer Program（¥688/年）。本产品只在一家公司内部使用，
使用者是个位数，分发路径可控（U 盘 / 局域网共享 / 内网下载）。

## 决策

**不买**（对应 PREP-CHECKLIST 决策 D8）。发布走 `scripts/release.sh` 默认分支：
未签名 universal dmg + SHA-256。`--signed` 分支保留，将来买了证书直接可用。

## 代价（必须让使用者知道，不是「以后再说」）

1. **Gatekeeper 拦截**：`spctl -a` 必然拒绝未签名产物。
   - U 盘 / 局域网共享拷贝 → **不打** quarantine 属性 → 双击直接开。
   - 网盘 / 浏览器下载 → **会打** quarantine → 首次需「系统设置 → 隐私与安全性 → 仍要打开」，
     或右键「打开」。
   所以分发方式不是偏好问题，直接决定 HR 第一次能不能打开。TC-600 的安装说明必须写这一条。
2. **Keychain 授权每次升级都会重置**（本条是真正的痛点）。
   钥匙串条目的 ACL 绑定在调用者的**代码签名**上。未签名应用的标识只能靠路径等弱特征维持，
   覆盖安装后旧条目会被判为「另一个程序在访问」，弹授权窗，甚至要求输入登录密码。
   处置：TC-601 专门演练升级后的处理步骤；TC-101 设计 Keychain 条目时要考虑
   「读不到旧条目」是**正常路径**而非异常，必须能引导重新初始化而不是直接报错。
3. 没有自动更新通道（本项目本来就不做自动更新，无额外损失）。

## 为什么仍然划算

¥688/年 换掉的是「每台机器首次手动放行」和「升级后一次授权弹窗」。
按个位数使用者、每月一次升级估算，人工成本远低于证书费用，
且这两件事都能靠一页安装说明消化。

## 重新评估的触发条件

- 使用者超过 ~20 台机器，或开始给第二家公司用 → 买。
- 升级后 Keychain 重置导致过一次数据事故（比如 HR 直接删了条目当重置用）→ 立刻买。
