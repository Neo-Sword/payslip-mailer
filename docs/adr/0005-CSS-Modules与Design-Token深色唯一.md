# ADR-0005 · CSS Modules + Design Token，深色唯一

日期：2026-11-11 · 状态：accepted

## 背景

原型 `payslip-mailer-design.html` 是单文件手写 CSS，十几个屏里散落着上百个十六进制色值。
直接照搬的后果是：改一个深色底要改 40 处，且不同组件会各自「差一点」地漂出
`#4a566c` / `#45516a` 这种肉眼分不出的近似值 —— 同一个角色两个颜色，后期无法统一。

## 决策

1. **样式方案：CSS Modules**（`*.module.css`）。不用 Tailwind（原子类会把「角色」拆散，
   与 Token 体系正交），不用 styled-components（运行时开销 + 与 Tauri 的 CSP
   `script-src 'self'` 配合麻烦）。
2. **色值只允许出现在 `src/styles/tokens.css`**，组件层一律 `var(--token)`。
   由 `scripts/gate.sh` 强制，确需脱离 Token 的颜色用行尾 `/* no-token: 理由 */` 显式豁免
   （可 grep、可审计），而不是关掉整条检查。
3. **只做深色一套**，不做浅色切换器。原型说「浅色仅替换 Token」，那是**架构承诺**，
   不是本期功能；真要做时补一套 token 与对比度复核即可，不用改组件。

## Token 的取舍规则：snap 还是 add

清理组件层硬编码色值时，每个色值二选一，规则必须写死，否则会变成审美投票：

| 条件 | 处置 |
|---|---|
| 与某既有 token 的 RGB 欧氏距离 **Δ≤10** | **snap** 到那个 token —— 但必须是**语义正确**的那个，不是最近的那个 |
| Δ>10 且没有对应角色 | **新增**一个按「用途-状态」命名的 token |
| Δ>10 但角色已有 token，只是当时随手取错色 | 改用既有 token（这是修 bug，不是加 feature） |

**「距离近 ≠ 角色同」，这是最容易做错的一步。** 两个现场记录：

- `#222a38`（表头底色）与 `--bg-card` `#1c2330` 距离 Δ5.7，按距离该 snap 进卡片；
  但表头画在卡片**内部**，同色会让表头与卡片糊成一片 → 新增 `--bg-well`（凹槽面）。
- `#3c475c`（按钮描边）与 `--line-modal` Δ3.3，按距离该 snap；但它是**控件**描边 →
  用 `--line-input`。

命名一律按「用途-状态」（`--ctl-hover`、`--bg-row-hover`、`--acc-strong-active`），
**不按色相**（不写 `--blue-400`）：换主题时改的是角色，不是颜色。

本轮按此规则清掉组件层 **54 处**硬编码色值，新增 **17 个**角色 token
（`--bg-well` / `--bg-row-hover` / `--ctl-hover` / `--ctl-hover-line` / `--switch-off` /
`--light-close` …）。

TC-000 验收时又抓到 3 处漏网（`App.tsx` 内联色值、`global.css` 滚动条两色），
其中滚动条按本规则**没有**就近并入数值相同的 `--line`，而是新建
`--scroll-thumb` / `--scroll-thumb-hover` —— 数值巧合不等于角色相同。
tokens.css 现有 **120** 个声明。

## 原型是交互权威，不是取色权威

原型 `:root` 只声明 **15** 个 CSS 变量，应用 tokens.css 有 **120** 个 —— 原型不是 token 来源。
它的内联色值在 P0 已被归一化进 token，剩下的偏差要按角色判断：

- 原型 `--line: #2a3140`，应用 `--line: #333d50`（Δ≈22，超出 snap 范围）。
  原因：原型的描边画在 `#0b0d12` 的演示页底上，应用的描边画在更亮的卡片面上，
  照搬会让描边看不见。**保留应用值**，并在 tokens.css 处注明。
- 反过来，原型明确定义过的角色（`.w-btn.pri` 主按钮、`.w-btn.dgr` 危险按钮）是权威：
  本轮发现组件里的主/危险按钮色**已经漂离原型**，token 化顺带修回了这个视觉回归。

## 门禁的第二条：引用必须可解析

大规模改名唯一的静默失败是**拼错 token 名**：`var(--不存在的名)` 不报错、也没有颜色，
在深色背景上表现为一片空白，肉眼极易漏过。所以 gate.sh 除了「不得泄漏色值」，
还检查「每个 `var(--x)` 都能在 tokens.css/global.css 找到声明」。
这两条合起来才让 token 体系可以自我校验，而不是靠人记住 120 个名字。

## 后果

- 正面：换主题 = 换一份 token 文件；视觉回归可被门禁抓住；组件文件里搜不到色值。
- 负面：新增一个视觉状态要先加 token 再写组件，多一步。这是刻意的摩擦。
- 负面：红绿灯这类**操作系统固定色**必须豁免或单独命名。本项目选择单独命名
  （`--light-close` 等）而不是并入 `--dang/--warn/--ok`：那三个是业务状态语义，
  这里是窗口控件，混用会让「红色」在未来主题里被迫一起变。
