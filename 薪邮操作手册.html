01认识薪邮：它做什么、数据在哪

先建立三个正确的预期，后面的操作才不会拧。

薪邮做什么

把每个人自己的工资条，用邮件单独发给本人。它管三件事： 管数据（每月一份加密的工资表）、管发送（逐人独立成信、限速、留证据）、 管证据（谁、什么时候、发给谁、服务器收没收 —— 可导出凭证，留存 ≥2 年）。

数据的全部家当都在这台 Mac 上

位置内容
~/Library/Application Support/PayslipMailer/data.db 唯一的持久数据（AES-256 整库加密）。工资数值只活在这里。
macOS 钥匙串（cn.payslipmailer.*） 数据库密钥、发信专用密码。不落盘、不进数据库。
…/PayslipMailer/exports/ 你主动导出的东西：空模板 xlsx、CSV 凭证、加密备份 zip。

三条贯穿全产品的规则

① 一人一封：每封邮件只有一个收件人，系统里没有「抄送/密送」这个功能； ② 数值不外流：日志、审计、凭证、备份文件名里都搜不到工资数值； ③ 只补不发过的：失败重试只针对没成功的邮件，永远没有「整批重发」。

02首次使用：安装与初始化

只做一次。做完之后进入「每月例行」。

  1. 双击安装包（dmg），把薪邮拖进「应用程序」。
  2. 首次打开应用 → 进入初始化向导。依次填写： 管理员邮箱（登录用的标识，也是找回数据的入口之一）、 登录密码（至少 10 位，这是打开本机工资数据的钥匙之一）、 单位名称（会出现在邮件的「公司名称」变量里，建议填）。
  3. 系统自动完成：创建加密数据库、写入默认的 7 个工资项与 1 套中文邮件模板。
  4. 进入工作台后，按 第 4 章做基础配置，按 第 5 章配好发信邮箱。

登录密码 = 数据的钥匙，丢了没有「重置」

工资数据是用「钥匙串里的密钥 + 你的口令」双层保护的。 口令忘了，本机数据打不开 —— 唯一的出路是用之前导出的加密备份恢复 （备份用的是另一个口令）。所以：初始化完成后，立刻做一次备份导出 （见 第 12 章），并把备份口令记在安全的地方。

03解锁、锁定与忘记密码

「锁」有两把：应用锁（口令）与空闲锁定（时间）。

场景会发生什么
打开应用 / 从锁屏进入输入管理员口令解锁。连续错 5 次锁定 60 秒。
放着不动（默认 10 分钟）自动上锁，密钥从内存释放。时长在 设置 → 安全与锁定 可改（5/10/30 分钟）。
合上盖子 / 休眠唤醒自动上锁（合盖即锁是设计行为，不是故障）。
想立刻锁⌘L。
口令忘了锁屏 → 「忘记密码」→ 用加密备份恢复（备份口令 ≠ 登录口令）。没做过备份 = 数据无法找回。

钥匙串授权弹窗（只出现在开发版）

首次启动若弹出「payslip-mailer 想要访问你的钥匙串中的密钥」： 输入开发钥匙串口令 xinyou-dev-keychain 并点始终允许。 正式安装包没有这一步。

04基础配置（一次做好，每月复用）

三样东西决定每月邮件长什么样：工资项、成员名单、邮件模板。

4.1 工资条项目 侧边栏 → 基础配置 → 工资条项目

工资表有哪些列，由这里决定。默认给出 7 项： 基本工资、绩效奖金、餐补、社保个人、公积金、实发工资（公式）、备注。

类型行为
文本原样显示（如备注）。
数字 / 金额千分位、右对齐；导入时可解析「18,000.00」「¥18000」等形态。
百分比0–100；「12.5%」这样的输入可以解析。
公式只读计算列。允许 + − × ÷ ( )、引用其他字段与汇总变量 应发合计 扣款合计（如 应发合计 + 扣款合计）。 导入与编辑时系统自动计算，别人填什么都不算数。
  • 必填勾选后：某行缺这一项 → 校验列标「××缺失」，该行进不了发送范围（能保存、能编辑，发送前才拦）。
  • 停用 ≠ 删除：停用的字段不再出现在新导出的模板里，但历史月份的数据与旧邮件不受影响。被历史数据引用的字段永远只能停用。
  • 改完立即试算一遍公式再保存（页面上有试算框）。

4.2 邮件组与成员 侧边栏 → 基础配置 → 邮件组与成员

  • 邮箱全局唯一：一个邮箱 = 一个人。一个人可以属于多个组。
  • 批量粘贴：从 Excel 复制两列（姓名、邮箱，制表符或逗号分隔）→ 粘贴 → 系统给出去重预览再入库。
  • 工号建议填：Excel 导入时用邮箱找人，工号用来做二次校验（不一致会提醒）。
  • 停用的成员不进入发送范围，但记录保留（名单里是灰的）。

4.3 邮件模板 侧边栏 → 基础配置 → 邮件模板

默认模板已按中文习惯写好。可插入的变量：

组变量
人员{{姓名}} {{工号}} {{邮箱}} {{组名}}
时间{{年月}} {{年份}} {{月份}}
单位{{公司名称}} {{回信邮箱}}
金额{{应发合计}} {{扣款合计}} {{实发工资}}（千分位格式化）
表格{{工资条表格}} —— 自动渲染成带样式的 HTML 工资明细表
字段{{字段.基本工资}} 等，随工资条项目动态生成

变量守门规则

模板里写了不存在的变量、或必填变量渲染出来是空的（比如单位名称没配置）→ 那个人在「预览与核对」里会被拦下。系统绝不把 「{{实发工资}}」这样的字面量发出去。

05配置发信邮箱（飞书专用密码）

侧边栏 → 系统 → 设置 → 邮件配置。只配一次。

  1. 在飞书桌面客户端（手机端不行）生成专用密码： 头像 → 设置 → 邮箱 → 第三方邮箱客户端登录 → 选择设备 → 生成。 前提：企业版邮箱，且管理员已开启「第三方邮箱客户端登录」。
  2. 回应用：SMTP 主机 smtp.feishu.cn、端口 465、加密 SSL、 用户名 = 你的完整飞书邮箱、专用密码 = 刚生成的串、 发件人名称（如「人力资源部」）、发件地址 = 同邮箱、速率建议 20–30 封/分。
  3. 点保存。专用密码只进 macOS 钥匙串 —— 数据库里只有「条目名」，搜不到密码。
  4. 点测试连接：系统给你的发件地址发一封自检信。收到它 = 配置通了。
测试连接的结果含义与下一步
✓ 自检信已交给服务器配置通了，去收件箱确认后即可发送。
认证失败（535）专用密码不对或已删除。回飞书桌面客户端重新生成 → 在这里更新。
连接失败主机/端口/加密方式不对，或网络不通。核对 ch.7 配置矩阵。

其他邮箱：QQ 邮箱（smtp.qq.com / 465 / 16 位授权码）、163（smtp.163.com / 465 / 客户端授权密码）、 腾讯企业邮（smtp.exmail.qq.com / 465）。授权码 ≠ 登录密码。

06每月例行流程总览

配置做好之后，每个月就是这一条线，熟练后约 10 分钟。

① 新建月份→ ② 导出空模板→ 财务填表→ ③ 导入→ ④ 核对 / 修正→ ⑤ 发送→ ⑥ 归档留证

月份账套的状态机（界面右上角的彩色标签）

草稿 draft→ 待发送 ready→ 发送中 sending→ 已发送 sent→ 已归档 archived
  • 草稿 / 待发送：可编辑工资数值。
  • 发送中 / 已发送 / 已归档：只读。发现发错了 → 解锁纠错（sent → 草稿， 系统自动在审计日志留一条修订记录），改完重新走待发送。
  • 列的口径：草稿用当前的字段配置；进入「待发送」那一刻冻结 —— 之后改工资项配置不影响这个月。

07导出空模板 → 交给财务填写

侧边栏 → 工资数据 → 导出空模板。

  1. 选月份 → 表头预览自动生成：3 个固定列（姓名 / 邮箱 / 工号）+ 启用的工资项。
  2. 选项：包含「填写说明」Sheet（默认开）；「2 行示例数据」与「预填成员名单」默认关 （预填名单会把姓名邮箱带出文件，需要时显式勾选）。
  3. 导出 → 文件在数据目录 exports/ 下，名如 薪资模板_2026-10.xlsx。
  4. 发给财务。表头已经做好：首行冻结、金额列数值格式 + 数据验证、 说明 Sheet 里写清了「扣款项填负数」「公式列不用填」。

给财务的三句话（写在模板的说明 Sheet 里）

① 扣款项（社保、公积金、个税）填负数——填正数实发会算错； ② 空格表示「这个人没有这项」，不要填 0； ③ 「实发工资」列是系统算的，不用填。

08导入工资数据（Excel 向导）

侧边栏 → 工资数据 → Excel 导入。上传 → 表头映射 → 校验与入库。

第 1 步 · 上传

选月份账套 → 选择财务填好的文件（.xlsx / .xls / .xlsb / .ods）。 原文件只读解析、不复制进应用。

第 2 步 · 表头映射

识别结果含义
精确列名与工资项完全一致 —— 直接采用，自己导出的模板全部精确命中。
模糊靠包含关系猜中的（如「员工邮箱」→ 邮箱）—— 需要你逐列确认。
未匹配系统里没有这一列（如「季度补贴」）。只能跳过，那一列的数据不会进库 —— 界面上会明说。真需要它就先去「工资条项目」加一项再重新导入。

姓名 / 邮箱 / 工号三个固定列必须各自对上一列，缺任何一个整批不能导。

第 3 步 · 校验与入库

档位判定（判据：会不会让发出去的钱是错的）后果
错误姓名/邮箱空、邮箱格式不对、成员不存在或已停用、 同一成员同月出现两次、金额解析不出、公式列被填了数字禁止入库；可下载错误明细（只有行号与原因，无数值）
警告姓名与成员名单不一致（按邮箱找人）、工号对不上可以入库，但带「身份待核对」标记 —— 该行不会进入发送范围
成功其余正常入库

冲突策略（这个月已有数据时必须三选一）

  • 覆盖：用导入的行替换已有记录。覆盖前自动在审计日志留痕（只有行数，无数值）。
  • 仅补充空白单元格：已有字段保留旧值，只填缺的（按字段计，不按整行）。
  • 取消导入：什么都不做。

入库的保证

整个批次是一个事务：中途任何一行失败，整批回滚，库里不会留半截数据。 导入后「实发工资」等公式列全部由系统重算，Excel 里填的值被忽略。

09逐格编辑、校验与合计

侧边栏 → 工资数据 → 月度工资表。

  • 改一格：点单元格 → 输入 → 回车/失焦保存 → 公式列（实发工资）当场重算。 每次保存都会整行重算内容校验和 —— 发送前的「内容一致」核对用的就是它。
  • 公式列不可编辑：界面上没有编辑入口，后端也会拒绝。
  • 校验列：必填缺失会标「××缺失」并计入表头「待处理」数 —— 警告不拦编辑，拦发送。改错了想撤销就改回来；缺一项就补一项。
  • 清空一格 = 这个人没有这一项（与 0 不同）。
  • 合计条：整月的应发 / 扣款 / 实发（不重复计公式列）。
  • 删除整行：给错了人要撤掉的场景（需确认；只删那一行）。
  • 逐格编辑不写审计日志 —— 审计的粒度是「导入、解锁、发送」这类成批动作。

10预览核对与发送

侧边栏 → 发送 → 预览与核对。这是发送前最后一道闸。

  1. 选月份 → 点核对发送范围。系统逐人做三重核对： 身份（导入时姓名存疑 / 成员停用 / 校验未通过 → 从范围排除）、 变量完整（必填变量或必填字段为空 → 拦）、 内容（发送前逐封比对内容校验和，改过数据会被发现）。
  2. 点任意一行可看逐人预览 —— 你看到的 HTML 与最终发出的邮件是同一份渲染。
  3. 全部通过 → 点发送 → 确认框写明「本次将向 N 人发送 N 封。每封邮件只有一个收件人，绝不抄送、绝不密送」。
  4. 确认后批次创建、任务逐封排队，以设置页的速率（默认 30 封/分）匀速出去。

发送过程中

情况系统的处置
服务器繁忙（4xx）自动退避重试（30 秒 / 2 分钟 / 10 分钟，最多 3 次），并把本批速率降速 50%。
地址被拒（5xx）标记失败不重试，批次继续发其余的人。
认证失败（535）立即中止整批 —— 引导去设置页更新专用密码。
网络断了自动暂停、保留现场；网络恢复后点「继续」。
强退 / 断电后重启提示「发现未完成的批次：已发 N / 总数」→ 继续。 已成功的人绝不会收到第二封。
有失败项提供「仅重试失败项」，永远没有整批重发。

被拦的人去哪了

核对报告里每个被拦的行都写明原因（身份待核对 / 已停用 / 基本工资缺失 / 变量是空的）。 处理完再点核对，通过后才允许发送 —— 这个检查在「确认发送」时还会再跑一遍， 即使你核对完又改了数据也逃不过。

11发送历史与 CSV 凭证

侧边栏 → 发送 → 发送历史。

  • 批次列表：状态、进度（已发 N / 总数）、速率、起止时间。
  • 逐封明细：姓名、收件地址、状态、尝试次数、SMTP 回码、失败原因分类、发送时间。
  • 导出 CSV 凭证：姓名、收件地址、状态、SMTP 回码、发送时间、内容校验和 —— 这就是《工资支付暂行规定》要求的「书面记录」，建议按年归档保存 ≥2 年。

凭证里没有工资数值

凭证证明的是「给这个人、这个时间、发了工资条、服务器收了」。 工资数值只存在于加密库里 —— 凭证会被存档、转发、打印，不能变成第二份明文。 校验和可以把凭证与加密库里的数据互相印证。

12备份、恢复与清空数据

侧边栏 → 系统 → 安全与备份。

加密备份（强烈建议每月发完薪后做一次）

  • 导出 = 整个加密库打包成 payslip-日期.zip，用你自己设的备份口令再加密一层。 备份口令与登录口令是两回事，互不派生。
  • 备份文件可以放到移动硬盘 / 网盘 —— 它离开本机也还是密文。
  • 换机 / 数据损坏 / 忘记登录口令：用备份恢复。恢复前系统自动给当前库做一次安全备份； 恢复是原子的 —— 中途失败不留半截文件。
  • 备份口令忘了 → 这份备份永久打不开（没有后门，也无法重置）。

清空数据（销毁权）

二次确认 + 输入管理员密码 → 数据库文件、钥匙串条目一并安全删除， 应用回到首启向导。清空前请确认备份已带走 —— 这是唯一不可撤销的操作。

13常见问题与故障排查

现象原因与处理
打开时弹「无法访问钥匙串」开发版首次运行正常现象：输 xinyou-dev-keychain 并点始终允许。正式包没有这一步。
提示「本机钥匙串里找不到需要的凭据」应用升级（未签名分发）会重置钥匙串授权。按界面引导重新初始化，或从备份恢复。
「本机加密数据打不开」密钥与数据不匹配或文件损坏。先试备份恢复；不要手工删除数据文件。
界面出现红色「只读」横幅数据结构版本与应用对不上（迁移漂移）。数据只能查看；从备份恢复或联系维护者。
测试连接 535专用密码不对/被删。飞书桌面客户端重新生成 → 设置页更新 → 再测。
导入时「错误 K 行」禁止入库按错误明细（行号+原因）改 Excel 后重新导入。常见：邮箱不在成员名单、金额列写了文字、公式列被填了数字。
核对时有人被拦「公司名称是空的」初始化时单位名称没填。设置页补上，或在模板里去掉 {{公司名称}}。
发送到一半停了看发送历史的失败分类：网络 → 点继续；认证 → 修密码；地址被拒 → 单独核对那个邮箱。
有人收到了两封仅发生在「断电恢复」的存疑任务上（发给本人的重复不构成隐私事故）。如介意，下次发送前先核对完再不改动数据。
忘记登录口令锁屏 → 忘记密码 → 用加密备份恢复。没有备份 = 无法找回。
